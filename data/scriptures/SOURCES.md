# 경전 데이터 출처

앱이 인용하는 문헌이 어디서 왔고, 어느 판본을 기준으로 옮겼고, 런타임 파일에 무엇을 싣는지 적는다.
구절 단위 정본은 `data/scriptures/경전 감수본 (감수후 v1).md` 이고, 제품이 읽는 파일은
`tools/build_scripture_seed.py` 가 그 마크다운에서 만든 `seed.json` 이다.

마지막 확인 2026-09-15 · 외부 문헌 감수 v1 반영본 기준

## 런타임에 무엇을 싣나

런타임 파일은 `seed.json` 과 `embeddings.json` 두 개다. 여기에는 셋만 싣는다.

1. 팔리 원문
2. 고전 한문 원문
3. 우리가 원문을 보고 새로 옮긴 한국어

하지 않는 것도 셋이다.

1. 현대 한국어 상용 번역서 문장을 그대로 옮겨 싣지 않는다
2. 현대 영어 번역 전체를 RAG 컨텍스트로 저장하지 않는다
3. 특정 현대 번역 하나를 그대로 다시 옮기는 방식으로 번역하지 않는다

## 지금 데이터가 이 규칙을 지키나

| 보는 것 | 결과 |
| --- | --- |
| `text` · `modern_gloss` · `daily_line` · `retrieval_text` 에 영어 문장 | 0건 |
| `seed.json` 전체에 남은 현대 영어 번역 문장 | 0건 |
| 임베딩에 넣는 글 | `retrieval_text` + `modern_gloss` + `text`. 전부 한국어다 |
| 모델 프롬프트에 넣는 칸 | `id` · `citation` · `modern_gloss` · `retrieval_text` · `text` |
| 런타임에 실린 원문 | 3구절(`maha.platform.3` · `zen.zhaozhou.fangxia` · `kr.wonhyo.hwajaeng`). 전부 한문이다 |

알아 둘 것 두 가지가 있다.

**현대 영어 번역은 저장소 안 마크다운에만 남아 있다.** 초안이 적어 둔 「옮긴 근거」에는 대조용으로
인용한 Bhikkhu Sujato 영역본 문장이 들어 있다. 그 마크다운은 사람이 감수할 때 읽는 문서라
런타임 파일이 아니고, 빌드가 `seed.json` 으로 옮기지도 않는다. Sujato 영역본은 CC0 라
인용 자체에 조건이 붙지 않는다.

**시판 한국어 번역서를 베끼지 않았다는 것은 아직 384구절에서 확인되지 않았다.** 초안은 팔리·한문
원문과 CC0 영역본만 보고 옮겼다고 적었고, 감수 항목 ②가 바로 이 확인이다. 지금까지 사람이
확인한 것은 16구절뿐이다. 나머지는 감수를 통과하기 전까지 운영에 나가지 않는다.

## 문헌별

`구절`은 `seed.json` 의 items 기준이다. 빠진 1구절은 세지 않았다.

### 팔리 문헌 350구절

디지털 정본은 전부 SuttaCentral 이다. 팔리 원문(Mahāsaṅgīti 판)을 받아 읽고,
Bhikkhu Sujato 영역본(CC0 1.0)을 뜻 대조에 썼다. 한국어는 그 둘을 보고 새로 옮겼다.
팔리 원문 자체는 저작권이 소멸했고 Sujato 영역본은 CC0 라 이용 조건에 걸리는 것이 없다.

## 화자를 어떻게 나누나

「불교 문헌의 문장」과 「부처님의 직접 발언」은 다르다. 법구경은 전승상 부처의 가르침이지만
어느 자리에서 한 말인지 화자가 특정되지 않고, 테리가타·승만경·선어록·원효 글은 아예 다른
사람이 말하거나 쓴 것이다. 서비스 이름이 「부처의 말」이어도 화자를 부처로 바꾸지 않는다.

| 화자 종류 | 구절 | 예 |
| --- | ---: | --- |
| `unknown` 아직 모름 | 383 | 감수 전에는 전부 여기다 |
| `canonical_tradition` 전승상 부처의 가르침 | 8 | 법구경 |
| `buddha` 부처의 직접 발언 | 2 | 상윳따 니까야 1:34 · 앙굿따라 니까야 2.33 |
| `zen_master` 선사 | 2 | 오조 홍인 · 조주 종심 |
| `nun` 장로니 | 1 | 뿐니까 |
| `disciple` 제자 | 1 | 법화경 신해품을 들려주는 네 제자 |
| `lay_bodhisattva` 재가 보살 | 1 | 승만부인 |
| `author` 저자 | 1 | 원효 |

`attribution.is_direct_buddha_speech` 는 `speaker_kind` 가 `buddha` 일 때만 참이다.
감수를 통과했다고 참이 되지 않는다.

## 빠진 구절

`kr.mangong.oneflower` 「世界一花」 한 건. `seed.json` 의 `items` 밖 `rejected` 에 비석으로만 남긴다.

네 글자가 만공보다 앞선 당나라 왕유의 《육조능선사비명》 게송에 `世界一花 祖宗六葉` 으로 확인되어,
만공이 만든 말이라고 적을 근거가 없다는 것이 감수 판정이다.

**`cn.wangwei.oneflower` 를 새로 만들지 않았다.** 이유는 셋이다. 감수가 확인한 것은 그 네 글자가
왕유의 비명에 나온다는 사실뿐이고 어느 판본의 어디인지는 확정되지 않았다. 새로 만들면 어차피
`needs_review` 로 들어가 운영에 나가지 않는다. 그리고 레코드를 만들려면 만공 귀속을 전제로 쓰인
초안의 현대적 풀이와 닿는 상황을 그대로 물려받게 되는데, 그 전제가 방금 철회된 것이다.
왕유 쪽으로 다시 세우려면 출처 확정과 본문 번역을 처음부터 다시 해야 한다.

## 다시 만드는 법

```bash
python3 tools/build_scripture_seed.py          # seed.json 을 다시 만든다
python3 tools/build_scripture_seed.py --check  # 감수본과 어긋나지 않았는지만 본다
LLM_API_KEY=... python3 tools/build_embeddings.py   # 씨앗이 바뀌면 벡터도 다시 만든다
```

`seed.json` 을 손으로 고치지 않는다. 고칠 것은 감수본 마크다운이다.
씨앗을 바꾸고 벡터를 다시 만들지 않으면 런타임이 해시 불일치를 로그에 남기고 어휘 검색만 쓴다.
