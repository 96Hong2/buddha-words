# 부처의 말

고민을 쓰면 **사람이 감수한 법구경 구절**을 근거로 그 상황을 풀어 주고, 오늘 해 볼 수 있는 일 하나를 알려 주는 [앱인토스](https://developers-apps-in-toss.toss.im) WebView 미니앱.

명언을 하나 뽑아 주는 앱이 아니다. 성공 기준은 이 퍼널이다.

> 장난으로 들어옴 → 「답이 꽤 괜찮네」 → 「내 진짜 고민도 써볼까」 → 「이건 저장하고 싶다」 → 「친구한테 이 문장은 보내고 싶다」

**지금은 착수 전이다. 제품 코드는 0줄이고, 이 저장소에는 개발에 바로 쓸 계획·스펙·화면 시안이 들어 있다.**
판은 **v0.3**(2026-09-14)이다.

정본 순서는 **통합 개발 계획 > `docs/spec/` > PRD > 시안** 이다. `docs/plan/01~06` 은 폐기된 원안이라 각 문서 맨 위 배너를 먼저 읽는다.

## 이 제품의 규칙 일곱

어기면 심사에서 반려되거나 개인정보 사고가 난다. 전문은 [`docs/repo-seed/CLAUDE.md`](docs/repo-seed/CLAUDE.md).

1. **경전은 LLM 이 만들지 않는다.** 모델은 구절 id 만 고르고 본문은 서버가 DB 에서 채운다.
2. **고민 원문을 저장·로그·이벤트 어디에도 싣지 않는다.**
3. **위기 신호는 위로만 간다.** 감지되면 경전 답변을 만들지 않고 고정 창구 안내로 간다.
4. **광고는 두 자리뿐이다.** 답변이 끝난 뒤와 같은 날 두 번째 고민 앞. 첫 답변에는 광고가 없다.
5. **모델 id 와 프롬프트는 배포 산출물이다.** 환경변수로 갈아 끼우지 않는다(플랫폼 AI 운영 요건).
6. **문구는 해요체.** 「상담·치료·진단·처방」을 쓰지 않는다. 경구체는 「오늘의 부처의 말」에만.
7. **가벼운 입력을 쳐내지 않는다.** 「점심 뭐 먹지?」는 실패가 아니라 앱의 캐릭터를 보여 줄 기회다.

## 폴더

```
docs/
  PRD v0.3 …html          제품 정본. 눌러 보는 라이브 목업
  PRD v0.2 …html          오래된 정본 (맨 위 배너)
  plan/00-통합-개발-계획.md  최종 판정 v0.3
  plan/01~06              폐기된 축별 원안 (참고용)
  plan/v0.3-지시-원문…md    제품 결정 원문
  spec/                   코드 정본 4종 + 라우터 픽스처
  repo-seed/              CLAUDE.md · AGENTS.md · .claude/rules 6개
design/                   화면 시안 7장 · 컴포넌트 · 색 토큰 (편집 원본)
assets/                   부처 일러스트와 화면 에셋
tools/                    인라인 사본 생성 · 보는 묶음 배포 스크립트
```

`design-inline/`(이미지를 base64 로 박은 사본)은 커밋하지 않는다. 필요하면 만든다.

```bash
python3 tools/inline_assets.py
```

## 라우터 픽스처 돌리기

의존성이 없다. Node 22 이상이면 그대로 돈다.

```bash
node --experimental-strip-types docs/spec/router.test.ts
# 20/20 통과
```

「ㅋㅋㅋㅋ」 열 줄이 LIGHT 로, 「남편이 다른 사람을 만나는 것 같아요. 이혼해야 할까요?」 22자가 DEEP 으로 가는지를 이 픽스처가 지킨다.

## 쓰는 글꼴과 색

본문·UI 는 [Pretendard](https://github.com/orioncactus/pretendard), 제목·경전·인용은 [MaruBuri](https://hangeul.naver.com/font/maruburi). 색은 모래·금색·세이지·연꽃 네 계열이고 대비비를 전부 계산해 통과시켰다. 값은 [`design/foundations/_tokens.css`](design/foundations/_tokens.css).
