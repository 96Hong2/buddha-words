## 1. 광고

### 1.1 전면·보상형은 같은 API 하나다

공식 원문 (`documentation/common/monetization/iaa/interstitial-rewarded-ad.md`):

> **전면형(Interstitial)** 과 **보상형(Rewarded)** 광고 모두 동일 API(`loadFullScreenAd`, `showFullScreenAd`)를 사용하며, 광고 타입은 광고 그룹 ID(adGroupId)를 기준으로 자동 결정돼요.

SDK 3.2.0 타입 정의에 실제로 있다 (`node_modules/@apps-in-toss/web-framework/dist/index.d.ts:637, 650`).

```ts
declare const loadFullScreenAd: ((params: {
  options?: LoadFullScreenAdOptions;   // { adGroupId: string }
  onEvent: (event: { type: "loaded" }) => void;
  onError: (error: Error) => void;
}) => () => void) & { isSupported: () => boolean };
```

`showFullScreenAd`의 이벤트: `requested` · `show` · `impression` · `clicked` · `dismissed` · `failedToShow` · `userEarnedReward`.

**세컨브레인 정정.** `앱인토스 플랫폼 규칙.md`는 "배너는 **TossAds** 만 쓴다. GoogleAdMob 쪽은 전면·리워드 전용이다"라고만 적어 뒀다. 지금 정본은 통합 API(`loadFullScreenAd`)이고, `GoogleAdMob.*`는 SDK 안에서 "v2 호환 별칭"으로 남아 있다(d.ts 660~663줄 주석). 새로 만드는 앱은 `GoogleAdMob.*`를 직접 쓰지 않는다.

### 1.5 배너를 넣는다면 (PRD에 없음, 선택)

전면·보상형만으로는 노출 수가 적다. 배너는 "노출 수 가장 많음 / eCPM 가장 낮음"이라 바닥을 깔아 준다.

- 넣을 수 있는 자리: **오늘의 말씀**, **보관함** 같이 스크롤되는 화면. 체크리스트 "배너 광고가 스크롤 가능한 화면에만 노출돼요"
- 넣으면 안 되는 자리: 고민 입력 화면, 생성 대기 화면, 답변 본문 중간(경전과 개인 풀이 사이). PRD 17절 전반부 판단 그대로
- 규격: 가로 100%, 높이 96px 권장, 컨테이너 내부는 비워 둔다
- 같은 화면에 같은 포맷 광고 2개 이상 금지
- 자리별 재요청 15초 쿨다운을 그대로 옮긴다(pocket `features/ads/AdSlot.tsx`)

## 2. 탭바 (PRD 25)

**판정: 조건부 가능.** 컴포넌트가 없으니 우리가 만든다.

원문(UI/UX 가이드):

> 탭바는 필수 컴포넌트는 아니에요. 다만 탭바가 필요하다면, 반드시 토스에서 제공하는 플로팅 형태의 탭바를 사용해서 **직접 구현**해야 해요. (...) 토스 메인 화면의 기본 하단 탭과 형태가 겹치면, 사용자가 현재 위치를 헷갈릴 수 있기 때문이에요.

탭 개수는 최소 2개 최대 5개. PRD의 3개는 범위 안이다.

**SDK도 TDS도 탭바를 주지 않는다.** TDS Mobile 컴포넌트 라우트 67개를 확인했을 때 TabBar·BottomTab·FloatingTab이 없었고, TDS의 `Tab`은 상단 가로 탭 스트립이다(세컨브레인 실측).

**그대로 가져올 것:** `pocket/frontend/src/app/AppShell.tsx`의 `TabBar` + `shell.css`의 `.tabbar` 블록. 화면 바닥에 붙은 바가 아니라 좌우 48px을 띄운 알약(pill) 모양이고, 바깥 영역은 `pointer-events: none`이라 아래 내용이 눌리지 않는다. 토스 기본 하단 탭과 형태가 겹치지 않는다.

**PRD 25절에서 고쳐야 할 것:** 「🔒 보관함(클릭하면 Premium 소개)」. 탭을 눌렀는데 곧장 결제 안내만 나오면 「파트너사 CTA 말고는 선택지가 없는 구조」로 읽힌다. 보관함 탭은 무료로도 볼 것(당일 답변, 오늘 저장한 것)을 먼저 보여 주고, 지난 기록 영역만 자물쇠로 흐리게 둔다.

### 화면별 처리 방침

| PRD 화면 | 제목 | 뒤로가기 |
|---|---|---|
| 홈(이야기하기) | 상단바의 앱 이름으로 충분. 본문 제목 없음 | 탭 루트. 누르면 미니앱 종료 |
| 생성 대기 | 제목 없음(전체 화면 연출) | 취소 가능하게 둔다. 취소하면 홈 |
| 답변 화면 | 본문 최상단에 「오늘의 답변」을 직접 그린다 | 홈으로 |
| 오늘의 말씀 | 본문 최상단에 제목 | 탭 루트 |
| 보관함 | 본문 최상단에 제목 | 탭 루트 |

### 뒤로가기 함정 (10초 가계부에서 이미 밟았다)

`graniteEvent.addEventListener('backEvent', {onEvent})`를 **구독하는 순간 플랫폼 기본 뒤로가기가 막힌다.** 등록했으면 이동·종료를 전부 우리가 처리해야 한다.

`pocket/frontend/src/app/BackHandler.tsx`가 정답 구조다. 세 단계로 처리한다:
1. 열린 오버레이가 있으면 그것부터 닫는다
2. 하위 화면이면 상위 화면으로 간다
3. 탭 루트면 미니앱을 닫는다(`Screen.close()`)

리스너는 화면마다 붙였다 떼지 않고 **한 번만** 붙이고 최신 핸들러를 ref로 갈아끼운다.

SSP 정책에도 걸린다: "Back 버튼을 차단하거나 비정상적으로 제어하여 사용자의 정상적인 화면 종료 또는 이전 화면 이동을 방해하는 경우"는 「광고 호출 동작 변조」 금지 행위다.

**미확인 하나.** pocket은 `document.title = SCREEN_TITLES[pathname]`을 계속 쓰고 있는데("제목은 document.title 로 넘긴다"는 주석), 세컨브레인은 "`document.title`을 읽지 않는다"고 단정한다. 둘 중 하나가 틀렸다. 실기기에서 화면을 옮기며 상단바 문구를 눈으로 확인해야 한다. 어느 쪽이든 **본문에 제목을 그리는 설계는 안전하다.**

## 5. 다크패턴 (PRD 19, 21)

금지 원문:

> - 서비스에 진입하자마자 전면을 막는 바텀시트. **알림 동의 바텀시트도 포함**
> - 뒤로 가려는 순간 이를 막는 바텀시트
> - 파트너사 CTA 말고는 선택지가 없는 구조

체크리스트:

> - 미니앱에 진입하자마자 바텀시트(토스 로그인, 알림 동의문 등)가 자동으로 나타나지 않아요.
> - 특정 화면 전환 시 바텀시트로 사용자의 행동을 강제로 유도하지 않아요.

| PRD | 판정 | 조건 |
|---|---|---|
| 21절 Paywall(⭐ 처음 누르면 안내) | 🟡 통과선 | 사용자가 ⭐를 눌러서 뜨는 것이라 「진입 즉시」도 「화면 전환 시」도 아니다. 단 ① 닫기 버튼 ② 시스템 뒤로가기로 닫힘 ③ 바깥 탭으로 닫힘 셋이 다 되어야 한다 |
| 19절 사용량 소진 | 🟡 위험 | 1.3 참고. 광고·결제 말고 나가는 길을 하나 더 둔다 |
| (PRD 미기재) 알림 동의 | ⚠ 주의 | 「내일 다시 물어볼 수 있다」(PRD 11절)를 하려면 알림이 필요한데, **첫 진입에 동의 시트를 띄우면 그 자체로 반려 사유다.** 답변을 한 번 받은 뒤 사용자가 「내일 물어봐 주세요」를 눌렀을 때만 `Notification.requestAgreement`를 부른다 |

10초 가계부 전례: 주소 파라미터(`?closing=1`)가 남아서 사용자가 누르지도 않은 전체화면이 다시 떴다. "'진입 즉시 시트 금지' 심사 항목을 우리 손으로 깬 것이다." 교훈은 **주소 파라미터는 상태가 아니라 이벤트다. 읽었으면 지운다**(`setSearchParams(..., { replace: true })`). 공유 링크로 들어오는 이 앱은 같은 함정에 더 가깝다.

## 6. 심사 리스크

### 6.1 이 앱은 「AI 채팅·상담」 서비스로 분류된다 (가장 큰 리스크)

PRD에 「상담」이라는 말이 이미 있다(19절 "오늘 무료 상담을 모두 사용했어요"). 분류를 피할 수 없다면 요건을 채우고 들어간다.

필수 운영 요건 원문 (`intro/caution.md` · `intro/guide.md` 공통):

> - 위험 키워드와 문맥을 함께 판단하는 필터링 시스템을 운영해 주세요.
> - 사용자가 금지된 요청이나 부적절한 질문을 했을 때는 명확하고 일관된 거절 응답을 제공해 주세요.
> - 자살·자해 관련 발화가 감지되면, 이용자 안전을 고려한 안전 응답 프로토콜을 적용해 주세요.
> - **AI 모델이나 프롬프트를 변경할 경우, 앱 배포 검토를 사전에 요청해 주세요.**
> - 부적절하거나 문제가 될 수 있는 응답이 발생했을 때 즉시 수정하거나 차단할 수 있는 운영 체계를 갖춰 주세요.
> - 동일한 AI 모델을 사용하는 자체 앱이나 웹 서비스가 있다면, 동일한 기준을 일관되게 적용해 주세요.

**PRD에는 이 여섯 개 중 하나도 없다.** MVP 범위에 다음을 P0로 넣어야 한다.

| 요건 | MVP 구현 |
|---|---|
| 위험 키워드 + 문맥 필터 | 입력을 LLM에 보내기 전 1차 규칙 필터, LLM 응답 후 2차 검사. PRD 4절 Router의 「안전도」 항목이 이 자리다 |
| 일관된 거절 응답 | 거절 문구를 하나로 고정한다. 매번 다르게 생성하지 않는다 |
| 자살·자해 안전 프로토콜 | 감지 시 **경전 답변을 생성하지 않고** 전용 화면으로 분기. 자살예방상담전화 109 등 공적 창구를 먼저 보여 준다. 이 화면에는 광고를 붙이지 않는다 |
| 모델·프롬프트 변경 시 사전 검토 | ⚠ **PRD 5절 모델 라우팅(Basic/Deep)이 바로 이 조항에 걸린다.** 라우터가 모델을 바꾸는 구조 자체를 심사 때 설명하고, 출시 후 모델 교체는 콘솔 사전 검토를 거친다. 「모델을 자유롭게 갈아끼운다」(PRD 28절)를 운영 자유도로 착각하면 안 된다 |
| 즉시 차단 체계 | 서버에서 프롬프트·차단어를 배포 없이 바꿀 수 있게 둔다 |

AI가 생성·제공하면 안 되는 콘텐츠도 명시돼 있다: 불법·범죄 / 약물·도박 / **폭력·자해·자살** / 선정성 / 혐오·차별 / 허위 정보·극단 행동 유도 / 개인정보 수집 유도.

우회 요청도 전부 차단 대상이다: "소설이나 영화 설정임을 전제로 한 요청", "교육용, 참고용, 이론 설명을 명목으로 한 요청" 등.

### 6.2 생성형 AI 고지·표시 의무 (법적 리스크)

원문 (`intro/guide.md` 2-4):

> **사전 고지 의무** 사용자가 서비스를 처음 이용하거나 생성형 AI 기능을 처음 쓰는 시점에, 그 서비스나 기능이 생성형 AI를 활용한다는 사실을 사용자가 인지할 수 있도록 고지해야 해요.
>
> **표시 의무** 사용자에게 노출되는 결과물이 생성형 AI로 만든 것이라면, 사용자가 AI 결과물임을 명확히 인식할 수 있도록 표시해야 해요. (라벨, 배지, 워터마크처럼 사람이 즉시 인식할 수 있는 방식)
>
> 관련 법령에 따라 최대 3,000만 원의 과태료가 부과될 수 있어요.

PRD가 부분적으로만 대응하고 있다. 7절 ②에 "부처의 직접 발언이 아니라 AI가 풀어쓴 내용이라면 「오늘의 한마디 · 현대적 해석」이라고 명확히 표시한다"가 있는 것은 좋다. 하지만:

| 필요 | PRD 현황 | 조치 |
|---|---|---|
| 첫 이용 시 사전 고지 | 없음 | 고민 입력 화면에 한 줄 고정: 「답변은 AI가 생성합니다」. 29절 개인정보 안내와 같은 자리에 둔다. **바텀시트로 띄우지 않는다**(진입 즉시 시트 금지) |
| 결과물 표시 | 7절 ②에만 있음 | 답변 화면 상단에 「AI 생성」 배지 하나를 상시로 둔다. 경전 원문(⑧)과 AI 해석(⑨⑩⑪)이 시각적으로 구분되어야 한다 |
| 공유 카드 | 없음 | 공유 이미지에도 「AI 생성」 표기를 넣는다. 카드가 앱 밖으로 나가는 결과물이다 |

### 6.3 종교 콘텐츠

- 종교(불교 포함) 콘텐츠 자체를 금지한 조항은 **서비스 오픈 정책·서비스별 주의사항 어디에도 없다.** 「종교」라는 단어가 두 문서에 한 번도 등장하지 않는다
- 명시 금지가 없다는 것이 승인 보장은 아니다. 정책에 "법률 위반 여부와 관계없이 토스의 브랜드 신뢰성, UX 정책, 리스크 관리 방침에 따라 등록이 제한될 수 있어요", "서비스 특수성이나 비즈니스 모델에 따라 사전 상담이나 추가 설명 요청이 있을 수 있어요"가 있다
- **판정: 미확인에 가까운 조건부.** 콘솔 채널톡으로 사전 문의하는 것이 출시 지연보다 싸다
- 지켜야 할 선: 특정 종파·사찰·단체로의 유입이나 후원 연결은 넣지 않는다. 정치 서비스가 출시 불가인 이유(중립성)와 같은 종류의 리스크다

### 6.4 의료로 읽히면 출시 불가

> **7) 의료 관련 서비스** 비대면 진료 제공·연결, 의료 행위로의 직접 연결, 병원 예약 기능 (...) 은 출시할 수 없어요.

PRD 10절이 "정신질환을 진단하거나 치료를 주장하지 않는다"고 이미 적어 둔 것은 정확하다. 문구 수준에서 더 내려간다.

| 쓰지 않는다 | 대신 |
|---|---|
| 상담, 심리 상담, 치료, 치유, 진단, 처방, 증상, 우울증·불안장애 같은 병명 | 이야기, 가르침, 풀이, 마음 |
| PRD 19절 "오늘 무료 상담을 모두 사용했어요" | "오늘 나눌 수 있는 이야기를 다 쓰셨어요" |
| PRD 1절 "AI 마음 수행 서비스" | 그대로 두어도 된다. 「수행」은 종교 용어지 의료 용어가 아니다 |

PRD 7절 ①의 "진단처럼 단정하지 않는다"도 그대로 살린다.

## 7. 기술 제약

| 제약 | 원문·근거 | 이 앱에서 |
|---|---|---|
| SSR 금지 | "서버 사이드 렌더링(SSR)은 사용할 수 없어요. 클라이언트 사이드 렌더링(CSR) 또는 정적 사이트 생성(SSG) 방식만" | Vite + React CSR. Next.js를 쓰더라도 `output: export` 아니면 안 된다 |

| eval 금지 | "외부에서 전달받은 코드를 실행하는 기능은 사용할 수 없어요" | ⚠ **LLM이 돌려준 문자열을 `dangerouslySetInnerHTML`로 그리지 않는다.** 28절 JSON의 모든 텍스트 필드는 순수 텍스트로만 렌더한다. 마크다운을 허용하려면 화이트리스트 파서를 쓴다 |
| 자사 사이트로 이동 금지 | "브라우저 히스토리 조작이나 웹뷰 임베드 등 어떤 방식으로든, 자사 사이트(토스 도메인 외부)로 이동하거나 그 콘텐츠를 렌더링할 수 없어요" | 공유 링크 랜딩 웹(8.2)을 미니앱 안에서 열지 않는다 |
| HTTPS·wss만 | 체크리스트 | 백엔드는 Cloud Run HTTPS. 스트리밍을 SSE로 할 경우 https 위에서 |
| CORS origin | 3.x: `https://<appName>.web.tossmini.com` / `https://<appName>.private-web.tossmini.com`. 2.x origin으로 서비스되는 공지가 있어 **4개 모두 허용**이 안전 | 백엔드 CORS에 4개 등록 |
| 사용자 식별 | `User.getAnonymousKey()`, 토스 앱 5.232.0+. 공식 문서: "앱 삭제나 기기 변경이 있더라도 동일한 사용자라면 같은 값이 반환돼요" | 회원가입 없음(PRD 24절과 맞는다). ⚠ **세컨브레인 정정 필요**: `앱인토스 플랫폼 규칙.md`에 "키는 재설치하면 바뀌고"라고 적혀 있는데 공식 문서와 어긋난다. 공식 문서를 따른다. 이 사실 덕분에 IAP 심사 요건 「기기를 변경해도 이용권 유지」가 익명키만으로 충족된다 |
| 라이트 모드 강제 | 체크리스트: "미니앱 테마는 라이트 모드로 구현돼 있어요" | PRD 14절 색 팔레트(아이보리·베이지·연꽃 핑크)와 맞는다. 15절 「🌙 잠·걱정」의 어두운 이미지는 **이미지 안의 색**이라 문제없다. 앱 배경 자체를 다크로 뒤집지 않는다 |
| 확대·축소 금지 | "지도처럼 꼭 필요한 경우를 제외하고, 제스처 기반 확대·축소 기능은 비활성화돼요" | 긴 답변 본문이라 글자 크기 조절 요구가 나올 수 있다. 핀치 줌이 아니라 **앱 안의 글자 크기 설정**으로 푼다 |
| 2초 룰 | "스크롤, 터치, 화면 전환 등 인터랙션 반응이 2초 이상 지연되지 않아요" | LLM 생성은 훨씬 오래 걸린다. **PRD 13절의 순차 텍스트 로딩 UX가 이 조항의 대응책**이다. 화면 전환은 즉시 일어나고, 그 화면 안에서 진행이 보이면 된다. 다만 Deep 답변이 30초를 넘기면 이탈한다. 스트리밍 또는 단계별 출력을 검토한다 |
| 상태 유지 | "미니앱을 종료했다가 다시 접속해도 필요한 데이터가 유지돼요" | `Storage.setItem`(네이티브 영속) + 서버. 당일 답변은 종료 후 재진입에도 남아야 한다 |
| 지원 게이트 | `isMinVersionSupported()`는 **샌드박스에서 버전과 무관하게 항상 true**. 미지원 폴백은 QR 실기기 + 구버전 토스 앱이라야 확인된다 | 각 기능마다 `isSupported()`를 부르고 실패해도 본 기능은 돌게 한다 |
| 에러 판정 | 도메인 멤버는 미지원 시 **에러를 던진다**. `error.name === 'UNSUPPORTED_APP_VERSION'`으로 판정. 메시지 문자열로 판정하면 안 된다(한국어 안내문이라 영어 단어가 없다) | 브릿지 한 겹으로 감싸고 전부 try/catch |

## 8. 공유 (PRD 22~24)

### 8.1 이미지 공유 API가 없다 (PRD 22절 정면 충돌)

SDK 3.2.0의 공유 표면은 이것뿐이다.

```ts
declare const Share: {
  createLink: ({ path, ogImageUrl }: { path: string; ogImageUrl?: string }) => Promise<string>;
  sendMessage: (message: { message: string }) => Promise<void>;   // 텍스트 하나
};
```

`sendMessage`는 **문자열 하나만** 받는다. 이미지·파일을 네이티브 공유 시트로 보내는 API가 없다. PRD 22절 「공유 전용 카드를 자동 생성한다」를 이미지 그대로 공유하는 방식으로는 만들 수 없다.

| 대안 | 방법 | 평가 |
|---|---|---|
| **A. OG 이미지로 카드를 보여 준다 (권장)** | 서버가 공유 카드를 이미지로 렌더해 공개 URL로 둔다 → `Share.createLink({ path: 'intoss://buddha-words/s/<id>', ogImageUrl: 'https://.../card/<id>.png' })` → `Share.sendMessage({ message: 링크 })` | 카톡·SNS 미리보기에 카드가 그대로 뜬다. 링크를 누르면 토스 앱의 해당 화면으로 간다. OG 이미지는 Android 5.240.0 / iOS 5.239.0 이상에서만 동작하니 미지원이면 텍스트만 나간다 |
| B. 기기에 저장 후 사용자가 직접 공유 | `File.saveBase64({ ... })` (Android 5.218.0 / iOS 5.216.0) | 단계가 하나 늘어 공유율이 떨어진다. A의 보조로만 |
| C. 텍스트만 공유 | 오늘의 한마디 + 링크 | 가장 단순하고 항상 된다. MVP 1순위로 이것부터 켜고 A를 얹는다 |

주의: 체크리스트에 "공유 기능에서 `intoss-private://` 링크를 사용하지 않고 `intoss://` 스킴을 사용해요"가 있다. QR 테스트에서 받은 `intoss-private://` 주소를 코드에 굳혀 넣으면 그대로 반려다.

### 8.2 외부 링크 유입 (PRD 24절)

공유 링크를 받은 사람의 동선은 이렇다.

```
공유 링크 클릭
  └─ 토스 앱 설치됨  → 토스 앱 실행 → intoss:// 딥링크 화면으로 진입 → 미니앱
  └─ 토스 앱 없음    → iOS 앱스토어 / Android 플레이스토어
```

| PRD 24절 요구 | 판정 | 조치 |
|---|---|---|
| "공유 이미지·링크 클릭 → 공유된 말씀 → 짧은 해석 → CTA" | 🟡 조건부 | `Environment.initialURL`로 들어온 경로를 읽어 **공유 전용 진입 화면**을 만든다. 이 화면이 홈이 아니어야 한다 |
| "회원가입부터 요구하지 않는다" | 🟢 가능 | 익명키 기반이라 애초에 가입이 없다 |
| 토스 미설치자에게 웹으로 보여 주기 | 🔴 미니앱으로는 불가능 | 스토어로 튕긴다. 웹 랜딩을 따로 만들 수는 있지만 **미니앱 안에서 그 웹을 열면 안 된다**(자사 사이트 이동 금지). MVP 범위 밖으로 둔다 |

덧붙임: 앱인토스에 **공유 리워드** 기능이 따로 있다(친구 초대 완료 시 보상 지급, 체크리스트 항목 3개). PRD의 Growth Loop와 맞물리지만 MVP에서는 보류한다.

밟지 말아야 할 함정:

- `ait init`은 멱등하지 않다. 두 번 돌리면 `&& ait build`가 중복으로 쌓인다
- `create-ait-app`은 SDK를 3.1.1로 고정한다. Vite 프로젝트 + `ait init`이 낫다
- devtools 목의 익명키가 상수(`mock-anon-hash-xyz789`)라 모든 e2e가 백엔드에서 같은 사용자가 된다
- 목의 `Screen.close()`는 화면을 안 없애고 `history.back()`만 한다. "시트가 아니라 미니앱이 닫혔다"가 브라우저에서는 안 보인다
- 심사원은 며칠 뒤에 열어 본다. 임시 터널 주소로 빌드한 번들은 통과할 수 없다. **항상 떠 있는 공개 주소**로 다시 빌드해 올린다
