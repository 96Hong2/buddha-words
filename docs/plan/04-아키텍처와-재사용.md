> [!warning] 이 문서는 **원안**이다. 최종 판정은 [00-통합-개발-계획](00-통합-개발-계획.md) 이 한다.
> 이 문서만 읽으면 **폐기된 설계**를 그대로 가져오게 된다. 아래가 뒤집힌 자리다.

> - **응답 방식**: 동기 POST 한 방 → **2단 요청** (00 X3)

> - **`/extra` 엔드포인트**: 제외. 보상형 보상은 「다른 가르침」이 아니라 **소진 후 1회 추가 이용**이다
> - **사용량**: 확인이 아니라 **예약**이다. `consultations` 에 `pending` 행 + 멱등키를 먼저 insert 한다
> - **`brand.primaryColor`**: 아래 본문의 「연꽃 핑크」는 낡았다. → 00 M0 산출물의 값이 정본이다
> - **CORS origin** (2026-09-14): 3.1.1 부터 WebView 서비스 origin 이 `https://{appName}.apps.tossmini.com` 이다. 아래 본문의 `web.tossmini.com` 은 낡았다 (00 1.8절)
> - **결제·`/extra`·사용량** (2026-09-14, v0.3): 비소모품 이용권 결제와 Deep Extension 이 다시 들어왔다. 구조는 00 1.6절이 정본이다

## 2. 스택 확정

| 층 | 고른 것 | 10초 가계부와 같게 갈 이유 | 다르게 갈 이유(그리고 결론) |
|---|---|---|---|
| 프론트 | Vite 8 + React 19 + TS, **CSR 전용**, react-router, TanStack Query | 플랫폼이 SSR 을 금지한다. 그리고 전체 배관이 이미 검증돼 있다 | 없음. 같게 간다 |
| 스타일 | CSS 토큰 + feature 별 `<feature>.css` | 시안 대조를 계산된 스타일 덤프로 하는 방식이 이미 자리잡았다 | TDS 도입을 검토했으나 **기각**. pocket ADR-0002 가 이미 판단했고, 이 앱은 「현대적 명상 앱 + 불교미술」이라는 고유 톤이 제품 가치(PRD 14)다. 토스 기본 톤을 입히면 그 가치가 사라진다 |
| 상태 | 서버 상태는 TanStack Query, 화면 상태는 `useState`. 전역 스토어 없음 | 서버 상태를 전역에 복사하면 두 벌이 되고 반드시 어긋난다 | 없음 |
| 백엔드 | FastAPI + Python 3.13 + SQLAlchemy 2 + alembic + httpx | 기동 가드 · 본문 크기 문 · 익명키 검증 · LLM 포트가 전부 이 스택 위에 있다. 갈아타면 그 넷을 다시 짜야 한다 | Node 로 옮겨 프론트와 언어를 합치는 안을 검토. **기각.** 얻는 것은 언어 하나이고 잃는 것은 검증된 배관 전부다 |
| DB | Cloud SQL PostgreSQL 18 + **`pgvector`** | 관리형 하나로 관계형과 벡터를 같이 본다. Cloud SQL 은 pgvector 를 공식 지원한다(최근 0.8.1) | 전용 벡터 DB(Pinecone·Qdrant)를 검토. **기각.** 경전은 수천 행 규모라 인덱스 없이 순차 스캔으로도 충분하고, DB 를 하나 더 세우면 고정비와 시크릿과 장애 지점이 같이 는다 |
| LLM | provider 를 환경변수 하나로(`stub`·`openai`·`gemini`), 기본 `stub` | 키 없이 개발과 e2e 가 돈다. provider 를 바꾸는 것이 환경변수 한 줄이다 | **모델은 두 급으로 나눈다.** Basic 은 싼 모델(pocket 이 쓰는 `gpt-5.6-luna` 급), Deep 은 고성능 모델. pocket 은 「싼 것 먼저, 걸린 것만 비싼 것」이었고 여기는 「입력 길이가 급을 정한다」 라 갈림 조건이 다르다 |
| 임베딩 | provider 임베딩 API 1종. 경전 색인은 **배치로 한 번**, 질의는 요청당 1회 | 질의 임베딩은 한 건당 비용이 사실상 0 | 로컬 임베딩 모델을 검토. **기각.** 이미지 용량이 수백 MB 늘고 Cloud Run 콜드 스타트가 길어진다 |
| 배포 | Cloud Run(asia-northeast3) + Cloud Run Job(alembic) + Artifact Registry + Secret Manager | 이미 돌아가는 구조다. 스크립트가 멱등이라 다시 돌려도 안전하다 | **스케일 설정은 다시 잰다.** pocket 은 maxScale 3 · 동시 80 · 512Mi 인데, 이 앱은 요청 하나가 LLM 을 20~40초 붙잡는다. 동시 80 이면 한 인스턴스가 LLM 커넥션 80개를 든다. **동시 20 · maxScale 5 · 1Gi 로 시작하고 실측으로 조인다** |
| 프론트 호스팅 | 앱인토스가 한다. 우리는 `.ait` 번들만 올린다 | | |
| 부처 이미지 20장 | **번들에 넣는다**(webp) | 외부 호스팅이면 오프라인·느린 망에서 답변 화면의 주인공이 비고, 도메인 하나가 더 는다 | 번들 크기 상한이 **미확인**이다. 20장 × 150KB = 약 3MB 가 통과하는지 첫 업로드로 확인한다. 막히면 Cloud Storage + Cloud CDN 으로 옮기고 감정별 대표 1장만 번들에 남긴다 |
| 시크릿 | Secret Manager. 파일 마운트는 **시크릿 하나당 폴더 하나** | 같은 폴더에 둘을 적으면 배포가 통째로 실패한다(실측) | mTLS 인증서 · DB 주소 · LLM 키 · IAP 웹훅 서명키 |
| mTLS | 토스 서버 API(익명키 검증)에 필요. **인증서는 아직 없다** | pocket 과 같은 상태다. `TrustingAnonKeyVerifier` 로 로컬만 돌리고 운영에서 켜지면 기동을 실패시킨다 | 콘솔 문의로 발급 절차를 받아야 한다. 이것 없이 운영에 올리면 아무 문자열로 남의 데이터에 접근할 수 있다 |

## 3. 데이터 모델

### 3.1 가장 먼저 정할 것: 고민 원문을 서버에 저장할 것인가

**판정: 기본은 저장하지 않는다.**

| 축 | 판단 |
|---|---|
| 무엇이 걸려 있나 | 이 앱의 입력은 영수증보다 훨씬 민감하다. 불륜 · 자살 충동 · 회사 사람 험담 · 가족 갈등이 평문으로 들어온다. 유출되면 회복이 불가능하고, 익명키가 토스 계정에 붙어 있어서 「익명이라 괜찮다」가 성립하지 않는다 |
| pocket 전례 | ADR-0010 이 캡처 이미지를 **요청 안에서만** 살게 했다. 「이미지가 어디까지 갔다 사라지나」를 한 파일만 보면 답할 수 있게 한 것이 그 결정의 값이다. 같은 값을 여기서도 받는다 |
| 그래도 필요한 것 | PRD 20 의 「📚 지난 고민(날짜별 조회)」 |
| 해결 | **원문 대신 `digest` 를 남긴다.** Pass1 이 마음 태그를 뽑을 때 「그날 무슨 일이었는지」를 한 문장(40자 이내, 고유명사·숫자 제외)으로 함께 뽑는다. 목록은 그 한 문장으로 그린다. 상세는 저장된 답변 7블록이 그대로 복원한다 |
| 원문 보관은 언제 | Premium 이어도 자동이 아니다. **「내 고민 원문도 함께 보관하기」 스위치**를 켠 사람만. 켜는 순간 PRD 29 의 「내 고민이 저장됩니다」를 그 자리에서 보여 준다. 끄면 그 시점부터의 원문을 즉시 지운다 |
| 잃는 것 | 원문 없이 답변 품질을 사후 분석할 수 없다. 「왜 이 경전을 골랐나」를 되짚으려면 원문이 필요한데 없다. **그 대신 Pass1 이 만든 검색 질의문은 남긴다.** 개인 서사가 빠진 주제어라 위험이 낮고 검색 튜닝에는 그게 쓸모 있다 |

### 3.2 테이블

관계형 8개 + 벡터 1개다. 시간 컬럼은 전부 timezone 있는 UTC 로 저장하고, 「오늘」은 `users.timezone` 기준으로 계산한다.

| 테이블 | 핵심 컬럼 | 왜 이 모양인가 |
|---|---|---|
| `users` | `id` · `anon_key_hash`(sha256, unique) · `timezone`(기본 Asia/Seoul) · `first_seen_at` · `store_raw_concern`(bool, 기본 false) · `created_at` | 익명키 원문은 저장하지 않는다. pocket 은 알림 발송에 필요해 켠 사람만 원문을 뒀는데, MVP 에 알림이 없으므로 원문을 아예 안 갖는다 |
| `consultations` | `id` · `user_id` · `mode`(basic·deep) · `visual_theme` · `image_key` · `digest`(40자) · `search_query` · `raw_text`(**nullable, 스위치 켠 사람만**) · `model` · `escalated`(bool) · `elapsed_ms` · `idempotency_key`(unique) · `retain_until` · `created_at` | `retain_until` 이 PRD 29 의 「당일만」을 담는다. 무료는 사용자 시간대의 그날 자정, Premium 은 null(무기한) |
| `consultation_blocks` | `consultation_id` · `kind`(tags·core·scripture·explanation·analysis·actions·closing·extra) · `payload`(jsonb) · `seq` | PRD 28 의 JSON 을 통째로 한 컬럼에 넣지 않고 블록으로 쪼갠다. 이유: 보상형 광고로 추가되는 「다른 가르침」·「두 번째 관점」(PRD 18)이 **나중에 붙는 블록**이기 때문이다. 한 덩어리면 답변 전체를 다시 써야 한다 |
| `scriptures` | `id` · `collection`(법구경 등) · `chapter` · `verse` · `text_ko` · `text_original`(nullable) · `text_hanja`(nullable) · `source_label`(화면에 그대로 뜨는 문자열) · `license` · `translator` · `emotion_tags`(text[]) · `is_active` | **`license` 와 `translator` 를 필수로 둔다.** 한글 번역문에는 번역자 저작권이 있다. 이 컬럼이 비어 있으면 색인에서 뺀다. PRD 6 은 「검증된 DB」라고만 적고 출처 권리는 다루지 않았다 |
| `scripture_chunks` | `scripture_id` · `chunk_text` · `embedding vector(N)` · `model` | 경전 한 절이 짧아 대개 1:1 이지만, 긴 경전을 넣게 될 때를 위해 테이블을 나눈다. `model` 컬럼이 있어야 임베딩 모델을 바꿀 때 섞이지 않는다 |
| `favorites` | `user_id` · `consultation_id` · `block_kind`(core·scripture) · `created_at` · unique(user_id, consultation_id, block_kind) | PRD 21 의 ⭐. 「오늘의 한마디」만 담을지 경전까지 담을지 사용자가 고른다 |
| `usage_counters` | `user_id` · `usage_date`(사용자 시간대 날짜) · `base_used` · `reward_granted` · `reward_used` · unique(user_id, usage_date) | 하루 3회(PRD 19)와 광고 보상분을 **따로 센다.** 합쳐 두면 「광고를 몇 번 봤나」를 못 세고, 보상 상한을 못 건다 |
| `usage_events` | `user_id` · `created_at` · `kind` | 1분 버스트 창(pocket 전례)을 위한 자리. 하루 상한만으로는 몰아치기를 못 막는다 |
| `subscriptions` | `user_id` · `sku` · `status`(ACTIVE·CANCELED·PAUSED·EXPIRED) · `access_granted`(bool) · `expires_at` · `order_id` · `last_event_at` · `source`(webhook·client_sync) | **웹훅이 정본이다.** 클라이언트의 `getSubscriptionInfo` 결과는 웹훅 지연을 메우는 보정용이고 `source` 로 구분해 남긴다 |
| `trial_grants` | `user_id` · `kind`(favorite_trial) · `used_count` | PRD 21 의 「첫 저장 3회 체험」 |

**이벤트 로그 테이블은 만들지 않는다.** pocket ADR-0019 와 같은 이유다. 수집 경로가 둘이면 「무엇이 어디에 남는가」에 답할 수 없고, 우리가 만드는 순간 익명키를 로그에 직접 싣게 된다. 토스 `Analytics.log` 하나만 쓴다.

### 3.3 무료와 Premium 이 갈리는 자리

| 기능 | 무료 | Premium | 어디서 갈리나 |
|---|---|---|---|
| 답변 열람 | 당일만 | 무기한 | `consultations.retain_until`. 지난 것은 **지우지 않고 조회에서 막는다**. 구독하면 그날부터의 것이 다시 보인다고 오해하지 않게, 안내에 「구독 이후 상담부터 보관됩니다」를 적는다 |
| 지난 고민 목록 | 없음 | `digest` 기반 목록 | `retain_until IS NULL OR retain_until > now()` |
| ⭐ 간직하기 | 3회 체험 | 무제한 | `trial_grants` |
| 마음 기록 통계 | 없음 | 태그 집계 | `consultation_blocks` 의 tags 블록을 세면 된다. 원문이 없어도 성립한다 |
| 하루 횟수 | 3회 + 광고 보상 | 넉넉히(상한은 둔다) | `usage_counters` |

## 4. API 설계

### 4.1 응답 봉투: 앱인토스 방식을 우리 API 에 적용하지 않는다

| 질문 | 판정 |
|---|---|
| 토스 서버 API 의 「비즈니스 오류가 HTTP 200 + `resultType:"FAIL"`」 을 우리도 따를까 | **아니다.** 우리 API 는 HTTP 상태코드 + `{code, message}` 봉투를 쓴다(pocket 과 동일) |
| 이유 | 200 에 실패를 싣는 방식은 **부르는 쪽이 전부 조심해야** 성립한다. 브라우저 `fetch` 는 200 을 성공으로 보고, TanStack Query 도 그렇고, 에러 바운더리도 그렇다. pocket 에서 이미 표준 방식이 잘 돌았다 |
| 대신 지키는 것 | **토스 API 를 부르는 우리 백엔드 쪽에서만** 그 함정을 처리한다. `integrations/apps_in_toss` 한 모듈에 가두고 바깥에는 「검증 통과 여부」만 돌려준다 |
| 하나 더 | **500 응답에 CORS 헤더를 직접 붙인다.** starlette 의 `ServerErrorMiddleware` 가 `CORSMiddleware` 바깥이라 500 에만 헤더가 빠지고, 그러면 화면이 늘 「연결이 불안정해요」라고 잘못 말한다(실측 함정) |

### 4.2 상담 제출: 동기 POST + 멱등키

워커·큐·폴링을 두지 않는다.

| 안 | 판정 |
|---|---|
| 동기 POST 로 끝까지 기다린다 | **채택.** Cloud Run 타임아웃 300s 라 여유가 있고, 서버 구조가 가장 단순하다 |
| 202 + 폴링 | 기각. 백그라운드 실행이 필요한데 Cloud Run 은 응답을 반환한 뒤 CPU 를 스로틀할 수 있다. 워커를 따로 띄우면 고정비와 배포 대상이 는다 |
| SSE 스트리밍 | 기각. 부분 실패 처리가 복잡해지고, PRD 13 이 이미 대기 시간을 **연출**로 쓰기로 했다. 글자가 흘러나오는 것보다 「살펴보고 있어요 → 가르침을 찾고 있어요」 4단계가 제품 의도에 맞는다 |
| 끊기면 | **`Idempotency-Key` 헤더**를 받는다. 같은 키로 다시 POST 하면 서버가 이미 완성된 결과를 그대로 돌려준다. WebView 가 백그라운드로 가서 연결이 끊겨도 한 번 더 보내면 된다. 이게 워커 없이 재시도 안전을 만드는 자리다 |

### 4.4 상담 파이프라인 한 번의 흐름

```
POST /consultations {text}
  1. 본문 크기 문        8,000자 넘으면 읽기 전에 413
  2. 익명키 검증         mTLS · 10분 캐시
  3. 멱등키 조회         이미 있으면 그 결과 반환하고 끝
  4. 사용량 확인         하루 상한 · 1분 버스트. 여기서 아직 안 깎는다
  5. redact()           전화·이메일·주민번호·계좌 마스킹
  6. 라우터 판정         길이 + 문장 수 + 위험 키워드 → basic | deep | safety
     └ safety 면 LLM 을 안 부르고 전용 안내 화면으로 간다 (5절)
  7. Pass1 (싼 모델)     emotionTags · searchQuery · digest · visualTheme
  8. 경전 검색           태그 필터 → pgvector 유사도 → 후보 3개
  9. Pass2 (라우터 모델)  후보 3개 + 마스킹된 고민 → 답변 7블록
 10. 결과 검사           출처가 후보 안에 있나 · 블록이 다 있나 · 길이 · 금칙 표현
     └ 걸리면 무엇이 이상했는지 적어 Pass2 한 번만 재시도. 세 번째는 없다
 11. 저장 + 사용량 차감   성공했을 때만 센다
 12. 201 응답
```

**8단계에서 0건이 나오면 AI 에게 만들게 하지 않는다.** 감정별 대표 경전 폴백 세트(10종)에서 고르고, 그 사실을 `consultations.model` 옆 플래그로 남긴다. PRD 6 이 금지한 것은 「관련된 부처님 말씀 하나 만들어줘」이지 「후보를 못 찾았을 때 미리 정해 둔 것을 쓰는 것」이 아니다.

## 6. 검증 구조

지침은 「TDD 하지 않는다. 구현 먼저, e2e 화면 증명 한 겹」이다. 그 지침에 맞춘 최소 세트다.

### 6.1 e2e 로 본다 (devtools 목 + LLM 스텁, CI 에서 돈다)

| # | 무엇을 보나 | 왜 여기인가 |
|---|---|---|
| 1 | 첫 진입 → 고민 3줄 → 인디케이터 `●●●` → 제출 → 대기 문구 4단계 → 답변 7블록이 **순서대로** → 마지막 한마디 | 제품의 한 바퀴. 이게 초록이면 배관이 다 이어져 있다 |
| 2 | 짧은 고민은 Basic, 긴 고민은 「✨ 깊은 풀이」 배지 | PRD 5 의 보상 구조가 실제로 화면에 뜨는지 |
| 3 | 경전 「원문 보기」 펼침에 출처 문자열이 그대로 | PRD 8 |
| 4 | **공유 페이로드에 고민 원문이 없다.** 세 옵션 전부 + 실패 경로도 | PRD 23. 실패 경로가 오히려 위험하다 |
| 5 | ⭐ 3회 뒤 네 번째에서 paywall 시트 | PRD 21 |
| 6 | 하루 3회 소진 → 「광고 보고 1회 더」 → 목 리워드 성공 → 카운터 +1 → 한 번 더 상담 가능 | PRD 19 |
| 7 | 배너: `no_fill` 이면 자리가 **접힌다**(빈 칸 안 남김) · 15초 안에 돌아오면 재요청 안 함 · opt-out 이면 「광고 자리」 | pocket 의 네 자리 검증과 같은 자리 |
| 8 | 오프라인이면 제출이 막히고 **적던 글이 남는다** | 가장 화나는 실패다 |
| 9 | LLM 503 일 때 문구가 뜨고 **사용량이 안 깎인다** | 부분 실패에서 돈만 깎이면 신뢰가 끝난다 |
| 10 | 익명키 `UNSUPPORTED` → 업데이트 안내 | |
| 11 | **행동 로그에 고민 원문·경전 원문·digest 가 없다.** 성공·실패 둘 다 | pocket 이 배선을 끊어 찾은 자리다. 결과가 화면에 안 보이는 것은 자동으로 비어 있다 |
| 12 | 320px(iPhone SE 1세대)에서 답변 화면이 가로로 안 넘친다 | pocket 이 정한 하한 |

**테스트 계정 격리는 1번보다 먼저 만든다.** `window.__ait` 에 setter 를 걸어 익명키를 테스트마다 갈아끼우지 않으면 모든 워커가 한 사용자가 되고, 하루 3회 상한 때문에 **두 번째 테스트부터 전부 429** 가 된다. pocket 보다 이 앱에서 더 치명적이다.

**LLM 스텁 다이얼**을 새로 만든다. `window.__buddhaStub.patch({ mode, scriptureId, fail })` 로 Basic/Deep · 특정 경전 · 실패를 만든다. 새 검증 장치이므로 **이 자리 한 곳만** 일부러 깨뜨려 실제로 빨개지는지 확인한다. 회차마다 하지 않는다.

Pass1 · Pass2-Basic 단가는 pocket ADR-0018 이 실제로 쓰는 `gpt-5.6-luna` 값($0.20 / $1.20)이다. Deep 급 모델 단가는 **가정이고 확인하지 않았다.**

## 8. PRD 와 어긋나는 지점

| PRD 절 | 무엇이 어긋나나 | 제안 |
|---|---|---|
| 6 (경전 DB) | 「검증된 DB」라고만 적고 **번역문의 권리**를 다루지 않는다. 법구경 한글 번역문에는 번역자 저작권이 있다. 출처만 밝히면 되는 문제가 아니다 | `scriptures.license`·`translator` 를 필수 컬럼으로 두고, 권리가 확인된 것만 색인한다. 공유 저작물 번역을 쓰거나 자체 번역을 만든다. **이건 착수 전에 답이 나와야 한다** |
| 5 (모델 라우팅) | 「안전도」가 Router 의 한 축으로만 적혀 있고, **자해·자살·타해 발화를 만났을 때 무엇을 보여줄지가 없다.** 「남편이 바람난 것 같아요」를 Deep 으로 승격하는 예시는 있지만 「죽고 싶어요」의 경로가 없다 | 라우터에 `safety` 갈래를 만든다. **LLM 을 부르지 않고** 전용 화면으로 간다: 마음을 받는 한 문장 + 상담 전화 안내 + 「그래도 이야기를 들려주시겠어요」 선택지. 이건 심사 리스크이자 법적 리스크다 |
| 20·21 (Premium) | **샌드박스에서 구독 기능 테스트를 지원하지 않는다**(공식 문서 원문). 최소 토스 앱 버전도 Android 5.248.0 / iOS 5.249.0(주문 생성), 목록 조회는 iOS 5.250.0 이다. MVP 1판을 낼 때 결제를 검증할 방법이 없다 | 1판은 ⭐ 3회 체험과 Paywall **화면까지만** 내고 결제 버튼은 사전 신청으로 둔다. 구독은 1.1판에서 실기기 실결제로 열거나, 구독 대신 일회성 상품(`createOneTimePurchaseOrder`, 5.219.0)으로 「30일 이용권」을 판다 |

## 9. 위험

| 위험 | 심각도 | 완화 |
|---|---|---|
| 경전 번역문 저작권이 미해결 | **치명** | 착수 전에 권리가 확인된 번역 소스를 확정한다. 못 구하면 자체 번역 범위와 일정을 별도 항목으로 뺀다 |
| 자해·위기 발화 처리 경로가 없다 | **치명** | 라우터의 `safety` 갈래를 P0 로 올린다. LLM 을 안 부르는 결정적 경로여야 한다 |
| mTLS 인증서가 없어 익명키 서버 검증을 못 한다 | 높음 | pocket 과 같은 상태다. 검증기를 인터페이스로 두고 운영에서 검증 생략이 켜지면 기동을 실패시킨다. 콘솔에 발급 절차를 물어야 한다 |
| Deep 무료의 LLM 비용 | 높음 | 하루 Deep 상한 + `consultations.model` 로 실사용 분포를 세고 조인다 |
| 구독을 샌드박스에서 검증할 수 없다 | 높음 | 1판에서 결제를 빼거나 일회성 상품으로 시작한다 |
| 요청 하나가 LLM 을 20~40초 붙잡아 Cloud Run 동시성이 무너진다 | 높음 | 동시 20 · maxScale 5 · 1Gi 로 시작. LLM 타임아웃을 Pass1 8초 / Pass2 25초로 못 박아 최악 왕복을 60초 안에 가둔다 |
| 보상형 광고 시청을 서버가 검증할 수단이 없다 | 중간 | 1회용 `adToken` + 30초 간격 + 하루 3회 상한. 검증 API 유무를 콘솔에 문의 |
| 답변 생성이 길어 대기 화면에서 이탈 | 중간 | PRD 13 의 4단계 연출을 **실제 진행 신호에 붙인다**(Pass1 끝 → 2단계, 검색 끝 → 3단계). 가짜 타이머만 돌리면 느릴 때 문구가 먼저 끝난다 |
| `.ait` 번들 크기 상한 미확인 | 중간 | 첫 업로드로 확인 |
| pgvector 확장을 Cloud SQL 인스턴스에서 켜야 한다 | 낮음 | `CREATE EXTENSION vector` 를 alembic 마이그레이션 첫 줄에 둔다. **pytest 가 SQLite 로 돌면 이 DDL 이 깨져도 초록이다.** pocket 의 migrations CI 잡(실제 PostgreSQL)이 이 자리를 지킨다 |
| devtools 목 내부 구조(`window.__ait`)에 기대는 격리 장치가 조용히 무너짐 | 낮음 | fixture 가 실제 요청의 `X-Anon-Key` 를 관찰해 기대값과 다르면 그 자리에서 실패시킨다 |

## 10. 아직 확인하지 못한 것

1. Deep 급 모델의 실제 단가. 7.2절의 $1.25 / $10 은 가정이다.
2. `.ait` 번들 크기 상한.
3. 보상형 광고 시청을 서버가 검증하는 API 가 있는가.
4. mTLS 클라이언트 인증서 발급 절차(공개 문서에 없다).
5. QR 테스트로 연 앱의 `Environment.environment` 가 `toss` 인가 `sandbox` 인가. pocket 도 아직 확인 못 했다.
6. pocket 이 하단 탭바로 심사를 통과했는가.
7. 경전 번역문 중 권리 문제가 없는 소스가 실제로 존재하는가.
8. IAP 웹훅의 서명 검증 방식(문서의 페이로드 예시에는 서명 필드가 안 보인다).
9. 앱인토스 MCP `search_docs` 는 모든 쿼리에 0건을 준다. 문서는 `llms.txt` + URL 에 `.md` 를 붙여 읽었다.
