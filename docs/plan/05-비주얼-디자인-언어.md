# 부처의 말 · 비주얼 디자인 언어 v1.0

> [!warning] 이 문서는 **에셋 도착 전 원안**이다. 색·타이포·이미지 절이 통째로 낡았다.
> **색과 타이포의 정본은 `design/foundations/_tokens.css` 다.** 최종 판정은 [00-통합-개발-계획](00-통합-개발-계획.md) 1.1절이 한다.
> 머리말의 「이 문서만 보고 시안 HTML 을 만든다」는 **더 이상 유효하지 않다.** 시안은 이미 에셋 기준으로 나와 있다.
>
> - **다크 모드**: 다크 팔레트 16쌍과 밤 일러스트 10장을 **통째로 뺀다.** 라이트 전용이다 (00 X1)
> - **색 램프 전체**: 아래 2.9절의 `:root` 블록은 **폐기됐다.** 에셋 이미지에서 다시 뽑은 `_tokens.css` 가 정본이다
>   (예: sand-50 이 `#FDFBF7` → `#FFFAF1`, lotus-600 이 `#B34557` → `#9A4356`)
> - **강조색**: 연꽃 핑크 → **금색 하나.** `--accent` 는 gold-500 `#AE8340` 이다
> - **`brand.primaryColor`**: 2.8절의 `#B34557` 은 폐기됐다. → 00 M0 산출물의 값이 정본이다
> - **이미지 장수**: 20장(감정 10 × 낮밤 2) → **8장**, 라이트 전용 (00 X8)
> - **이미지 해상도**: 1290×720 은 아직 **없는 값**이다. 받은 부처 이미지는 173~178 × 185~193 px 다 (00 1.1 A4)
> - **본문 폰트**: Pretendard 하나 → 본문·UI 는 **Pretendard**, 제목·경전·인용은 **MaruBuri** (00 1.1 A3)
> - **아이콘 3안**: 8.1절의 「바탕이 브랜드 컬러」 전제는 낡았다. 실제 받은 아이콘은 아이보리 바탕에 금색 선화다
>
> 살아 있는 것: 로딩 규칙(`@import` 금지·비차단·폴백 스택 필수), 대비 계산 방식, 짙은 면 사고 방어 C-1~C-5, 8단 타이포 근거.
> - **v0.3 (2026-09-14)**: 부처 이미지는 고해상 자세 6종 × 배경 시간대 4 로 바뀌었다(`docs/spec/visual-theme.ts`). 감정별 그림 재생성은 하지 않는다

## 0. 이 문서를 읽는 법

- 출발점은 `docs/PRD-v0.1.md` 14~16절이다. 거기서 정하지 않은 것을 여기서 토큰까지 못 박는다.

## 2. 컬러

### 2.1 왜 이 다섯인가, 그리고 어떻게 역할을 갈랐나

PRD §14 가 준 것은 색 다섯의 **이름**뿐이다. 다섯을 나란히 두면 P3 을 어긴다. 역할을 갈라 둔다.

| 계열 | 역할 | 화면 점유 목표 | 근거 |
| --- | --- | --- | --- |
| **sand** 아이보리·연한 베이지 | 배경·표면·테두리·본문 잉크 | 60% | 60-30-10 배분(참고: [flextudio 앱 색상 가이드](https://flextudio.com/blog/app-design-color-guide)) |
| **sage** 세이지 그린 | 주조. 태그·성공·짙은 면·보조 버튼 | 20% | PRD §7 마음 태그가 가장 자주 보이는 채색 요소다 |
| **gold** 따뜻한 금색 | 경전 영역 전용 강조. 인용면·출처·오늘의 한마디 장식 | 10% | PRD §8 "실제 경전"은 신뢰의 핵심이라 시각적으로 따로 서야 한다 |
| **lotus** 연꽃 핑크 | 강조 하나. 주 버튼·링크·포커스·브랜드 | 10% | 강조는 하나여야 한다. 연꽃이 제품 이름과 가장 가깝다 |
| **night** 따뜻한 밤색 | 다크 테마 지반 | (다크 전용) | PRD §15 "어두운 남색 대신 **따뜻한 밤색**" 원문을 그대로 따른다 |

기각: **다섯을 모두 강조로 쓰는 안.** PRD 문장을 문자 그대로 따르면 한 화면에 다섯 색이 선다.
10초 가계부에서 같은 문제를 반대 방향으로 겪었다: "PRD 는 토큰 9개만 정의했는데 시안은 30개를 쓴다.
PRD 에 없으면서 가장 많이 쓰인 색이 `#8B9096`(142회)과 `#FFFFFF`(89회)다. 카드 흰색이 배경 위에 얹히는
2층 구조라 PRD 만 보고 만들면 카드와 배경 대비가 사라진다."
그래서 이번에는 **PRD 에 없는 중립 계열(sand 10단계 + 잉크 3개)을 먼저 정의**하고 시작한다.

### 2.7 짙은 면 사고를 막는 규칙 (10초 가계부에서 실제로 난 사고)

> 원문: "월간 결산을 시안대로 짙은 세이지 전면으로 바꿨더니 「다음」 버튼이 사라진 것처럼 보였다.
> 버튼 바닥색이 `sage-700` 인데 배경도 `sage-700` 이라 대비가 1:1 이 됐다. 시안은 버튼을 **크림 카드 안**에
> 두고 있었다. 배경색을 바꿀 때는 그 위에 놓인 것들이 같은 토큰을 쓰고 있는지 먼저 센다.
> 이 화면에서는 점·제목·링크·버튼 넷이 그 색이었다."

부처의 말은 「오늘의 한마디」를 짙은 면으로 낼 가능성이 높아 **같은 사고가 날 자리가 이미 있다.** 규칙으로 막는다.

- **C-1.** 면(배경) 토큰을 바꾸는 변경은 그 면 위에 놓인 **모든** 요소의 토큰을 세어 보고 판정한다. "한 값만 바꾸면 된다"는 지적은 그 값을 쓰는 자리를 다 센 뒤에 받는다.
- **C-2.** 같은 램프의 인접 두 단계를 면과 그 위 요소에 함께 쓰지 않는다. 아래 표가 근거다.
- **C-3.** 짙은 면 위에 놓을 수 있는 것은 아래 「배치 가능」 목록뿐이다. 새로 놓고 싶은 색이 생기면 계산부터 한다.
- **C-4.** 짙은 면 위 버튼은 **램프를 건너뛴다.** 짙은 세이지 면 위 버튼은 sand-50 바닥 또는 gold-300 바닥이다.
- **C-5.** 검증은 눈이 아니라 계산으로 한다. 10초 가계부 원문: "시안 대조는 눈이 아니라 계산된 스타일 덤프로 한다. (...) 사람 눈은 2px 을 못 본다."

```css
  --ph-loss: var(--c-lotus-900);        --ph-comparison: var(--c-night-2);
  --ph-choice: var(--c-sage-900);       --ph-sleepless: var(--c-night-2);
  --ph-attachment: var(--c-lotus-900);  --ph-emptiness: var(--c-night-1);
  --ph-relationship: var(--c-sage-800); --ph-approval: var(--c-gold-900);

  /* 다크에서는 그림자가 안 보인다. 층은 표면 밝기로 만든다 */
  --sh-card:   none;
  --sh-raised: 0 8px 24px rgba(0, 0, 0, .45);
  --sh-tabbar: 0 8px 24px rgba(0, 0, 0, .50);
}
```

⚠ Tailwind 를 쓴다면 10초 가계부 함정을 그대로 밟는다: "`@theme static` 이 붙어 있어야 한다.
안 붙이면 tailwind 가 **클래스 이름에서 안 쓰인 변수를 지운다.** 도넛 램프는 JS 가
`var(--color-donut-N)` 문자열을 만들어 쓰는데 tailwind 는 그걸 못 본다. 실제로 그것 때문에 운영 빌드에서
도넛 조각이 통째로 안 보였다." **이 문서의 `--ph-*` 열 개가 정확히 같은 모양이다**(JS 가
`var(--ph-${theme})` 로 만들어 쓴다). Tailwind 를 쓰면 `@theme static` 에 넣는다.

## 3. 타이포그래피

### 3.1 폰트 선택과 로딩

**Pretendard Variable** 을 쓴다. 10초 가계부에서 이미 한국어 본문으로 검증된 서체이고, fallback 스택이
그대로 돌아간다(확인됨: `pocket/frontend/src/index.css` 의 `--font-sans`).

**로딩 방법은 함정을 그대로 피한다.**

> 10초 가계부 원문: "e2e 가 `page.goto` 에서 30초 타임아웃으로 간헐 실패했다. 원인은 우리 코드가 아니라
> `index.css` 맨 위의 `@import url(cdn.jsdelivr.net/...pretendard...)` 였다. CSS 안의 `@import` 는
> **그 시트를 다 받을 때까지 렌더를 막는다.** CDN 이 느리면 화면이 안 뜬다. 미니앱은 열자마자 보여야 하는
> 자리라 테스트 문제가 아니라 출시 문제다."

| 규칙 | 내용 |
| --- | --- |
| 절대 금지 | CSS 파일 안의 `@import url(...)` 로 폰트 받기 |
| 채택 | `index.html` 에서 `<link rel="stylesheet" href="..." media="print" onload="this.media='all'">` 비차단 로드 |
| 필수 | fallback 스택. 못 받아도 읽힌다 (`-apple-system, BlinkMacSystemFont, system-ui, 'Apple SD Gothic Neo', 'Noto Sans KR', 'Malgun Gothic', sans-serif`) |
| 필수 | `font-display: swap` |
| 필수 | `font-synthesis-weight: none`. 가짜 굵기가 한글 받침을 뭉갠다 |
| 이 앱에만 있는 위험 | **본문이 800~1,300자라 폰트가 늦게 들어오면 본문 전체가 리플로우한다.** 짧은 화면보다 훨씬 크게 튄다 |

**미확인:** Pretendard 한글 서브셋을 번들에 자가 호스팅할지 CDN 비차단으로 받을지는 아직 안 정했다.
자가 호스팅하면 첫 화면이 우리 오리진만 기다리지만 번들이 커진다. 실측 용량을 보고 정한다(11절 미확인 6).

### 3.3 긴 본문이 실제로 어떻게 읽히는가 (계산)

미니앱 최소 폭 기기를 360px 로 잡고 좌우 gutter 20px, 카드 padding 20px 을 빼면 **본문 폭 280px**.

| 값 | 계산 | 결과 |
| --- | --- | --- |
| 한 줄 글자 수 | 280 ÷ 16 (한글 1글자 ≈ 1em) | **약 17.5자** |
| Deep 본문 1,300자 | 1300 ÷ 17.5 | **약 74줄** |
| 그 높이 | 74 × 28px | **약 2,070px** |
| 화면 몇 판 | 2070 ÷ 600(가시 영역) | **약 3.5판** |

→ 그냥 흘려 쓰면 3.5판짜리 글벽이 된다. 그래서 **세 가지를 규칙으로 박는다.**

1. **문단을 3~4개로 끊는다.** 문단 사이 `--s-4`(16px). LLM 프롬프트에 문단 수를 넣어야 실제로 그렇게 온다(9절 PRD 충돌 D).
2. **본문 폭을 카드 padding 16px 로 줄이지 않는다.** 폭을 줄이면 줄 수가 늘어 스크롤이 더 길어진다. 좌우 gutter 를 24 가 아니라 **20** 으로 정한 이유가 이것이다.
3. **`word-break: keep-all`** 로 단어 중간에서 안 끊기게 한다. 한국어는 어절이 끊기면 읽기가 크게 나빠진다. 긴 URL 대비로 `overflow-wrap: anywhere` 는 그 요소에만 따로 건다.

```css
.answer__read {
  font-size: var(--t-body-l);
  line-height: var(--lh-read);
  word-break: keep-all;
  letter-spacing: 0;
}
.answer__read p + p { margin-top: var(--s-4); }
```

### 3.4 「오늘의 한마디」 디스플레이 스타일

PRD §7 ②의 핵심 메시지이고, 그대로 **공유 카드의 헤드라인**이 된다(§22).

```css
.today-line {
  font-size: var(--t-display-l);      /* 26px */
  line-height: var(--lh-display);     /* 1.45 */
  letter-spacing: -0.02em;
  font-weight: var(--w-bold);
  word-break: keep-all;
  text-wrap: pretty;                  /* 미지원 브라우저는 무시한다 */
  color: var(--text);
}
.today-line__mark {                   /* 「현대적 해석」 꼬리표 (§7 원문) */
  font-size: var(--t-caption);
  font-weight: var(--w-medium);
  color: var(--text-muted);
}
```

- 26px 로 정한 이유: 본문 폭 280px 에서 26px 이면 한 줄 약 10.7자다. 40자 상한(7절)이 **4줄 이내**에 들어온다.
- 30px 이상으로 키우면 3줄이 넘어가 카드와 화면의 줄 수가 달라진다. 같은 문장이 두 곳에서 다르게 접히면 공유 미리보기가 어긋난다.
- `#B34557` 같은 강조색으로 통문장을 칠하지 않는다. 긴 문장을 강조색으로 칠하면 읽기가 나빠진다. 강조는 문장 안의 **한 구절만** `<strong>` 으로 `--accent-text`.

### 3.5 한국어 조판 공통 규칙

| 규칙 | 값 | 왜 |
| --- | --- | --- |
| 자간 | 본문 0, 큰 글자만 음수 | 한글은 음수 자간이 크면 받침이 붙어 읽기 나빠진다 (추정, 실기기 확인 필요) |
| 줄바꿈 | `word-break: keep-all` | 어절 중간 끊김 방지 |
| 숫자 | `font-variant-numeric: tabular-nums` | 「법구경 216장 4절」 같은 출처 숫자가 흔들리지 않게 |
| 문장부호 | 말줄임은 `…` 한 글자. `...` 세 점을 쓰지 않는다 | 폭이 들쭉날쭉해진다 |
| 텍스트 노드와 flex | **글자를 담은 상자에 `display:flex; gap` 을 걸지 않는다** | 10초 가계부 원문: "마크업에는 `남은 <span>23</span>일` 로 붙어 있는데, 그 줄이 `display:flex; gap:4px` 라 **텍스트 노드 하나하나가 flex 항목이 되어** 사이마다 4px 이 끼었다." 이 앱은 `#불안` 태그와 「법구경 216장」 같은 자리에서 똑같이 난다 |

### 4.3 그림자와 층

| 토큰 | 라이트 | 다크 |
| --- | --- | --- |
| `--sh-card` | `0 2px 8px rgba(42,38,34,.05)` | **none** |

**다크에서 카드 그림자를 끈다.** 어두운 지반 위 그림자는 안 보이고 대신 가장자리가 지저분해진다.
다크의 층은 그림자가 아니라 **표면 밝기**(night-0 → night-1 → night-2)로 만든다.

그림자에 순검정을 쓰지 않는다. 따뜻한 잉크(`42,38,34`)를 쓴다. 아이보리 배경 위에서 회색 그림자는 차갑게 뜬다.

| 부품 | 규격 |

| 경전 인용면 | 카드 **안쪽** 인셋. radius 16 · padding 16 · 배경 `--surface-scripture` · 왼쪽 세로선 3px `--scripture-rule` |

⚠ **한 컴포넌트가 「사라지는 것」과 「사라진 뒤에도 살아 있어야 하는 것」을 함께 들고 있으면 조기 return 이 둘 다 지운다**
(10초 가계부 실측). 공유 시트를 연 채 답변 카드가 조건부로 사라지는 구조를 만들지 않는다.

### 4.5 화면 골격 (상단바는 플랫폼 것이다)

```
┌──────────────────────────────┐
│  토스가 그리는 네비게이션 바   │ ← 우리가 안 그린다. 높이도 우리 것이 아니다
├──────────────────────────────┤
│  ↕ safe-area top = 0         │ ← ⚠ 여기를 우리가 더하면 안 된다
│                              │
│  [gutter 20] 콘텐츠 [20]      │
│                              │
│  ↕ 탭바 높이 + 24            │
├──────────────────────────────┤
│  ▢ 우리가 만드는 플로팅 탭바   │ ← SDK·TDS 가 안 준다
│  ↕ safe-area bottom          │
└──────────────────────────────┘
```

> 10초 가계부 원문: "실기기에서 「전체적으로 위 여백이 지나치게 많다」는 지적을 받았다. 재 보니 제목 위가
> **54px** 비어 있었다. 브릿지의 `getSafeAreaInsets()` 는 **기기의** 인셋(노치 높이)을 준다. 그런데 우리
> 웹뷰는 토스가 그리는 상단바 **아래에서** 시작한다. 그 자리는 이미 상단바가 먹었는데 우리가 한 번 더 더한 것이다.
> `SafeAreaProvider` 에서 `top` 만 0 으로 만든다. 값이 들어오는 자리를 막으면 한 곳으로 끝난다."

→ **규칙:** safe-area 는 provider 한 곳에서 `top: 0` 으로 고정한다. CSS 여러 곳에서 빼지 않는다.

`navigationBar.theme` 은 `'light' | 'dark'` **고정값**이라 본문 테마에 따라 바꿀 수 없다(3.2.0 타입 원문).
본문이 다크인데 상단바가 라이트면 이음매가 보인다. → 11절 미확인 1.

### 4.6 플로팅 탭바 (직접 구현)

| 답변 화면 본문 안 | ❌ | PRD §17 "답변 첫 화면 / 경전과 개인 풀이 사이" 금지 |
| 답변 끝 · 「다른 고민 이야기하기」 뒤 | ⭕ 전면 | PRD §17 광고 위치 1. 세션 경계 |
| 오늘의 말씀 | ⭕ 배너 | 스크롤 가능한 화면이다 |
| 보관함 | ⭕ 배너 | 같음 |

배너 컨테이너 규격(문서 원문): **가로 100% · 높이 96px 고정 · 안쪽은 비워 둔다 · 가로를 px 로 고정하지 않는다.**
자리별 재요청 간격 15초를 둔다(10초 가계부 `AdSlot` 에서 검증된 값).
배너에 **X 버튼을 넣지 않는다**(「광고 은닉 또는 겹침」 포괄 조항).

⚠ **일러스트와 배너 사이 32px + `--border` 구분선.** 원칙 P5. 정책이 요구하지 않아도 우리가 지킨다.

## 5. 부처 일러스트 20종

PRD §16: "MVP는 **감정 10종 × 배경 2종 = 20개** 고품질 이미지를 미리 제작."
PRD §15 는 그중 **6종만** 장면을 정의했다. 나머지 4종과 「배경 2종」의 정의가 비어 있다. 여기서 채운다.

### 5.1 「배경 2종」을 무엇으로 정할 것인가

| 안 | 내용 | 판정 |
| --- | --- | --- |
| **채택 · A안** | **낮(day) / 밤(night)**. 같은 자세·같은 구도, 주변 광원과 지반만 바뀐다. 낮은 아이보리 지반, 밤은 따뜻한 밤색 지반 | ✅ |
| B안 | 같은 감정의 다른 장면 두 컷(변주) | ❌ 기각 |
| C안 | 세로 히어로 / 정사각 공유용 (자르기 두 벌) | ❌ 기각. 이건 배경이 아니라 크롭이다. 한 장에서 잘라 쓰면 된다 |

**A안 근거**
- 앱인토스 공식 UX 가이드 원문: 그래픽은 "다크 모드와 라이트 모드 모두에서 잘 보여야 해요". 아이보리 일러스트 한 벌만 만들면 다크 화면에서 통째로 떠 보인다.
- PRD §15 가 이미 밤을 말하고 있다: "🌙 잠·걱정: 달빛, 작은 연꽃등, **어두운 남색 대신 따뜻한 밤색**".
- 10초 가계부는 라이트 전용(`color-scheme: light`)이라 이 문제를 피해 갔다. 부처의 말은 **밤에 열리는 앱**이다(PRD §15 에 잠·걱정 감정이 있다). 다크를 포기할 수 없다.

**B안을 기각한 이유:** 변주 두 컷을 만들면 20장 중 10장이 다크에서 못 쓰인다. 재방문 지루함은 이미지가 아니라
**문구·모션**으로 푼다(제작비 0). 대기 화면 문구 4줄과 마지막 한 문장이 매번 달라진다.

### 5.2 감정 10종 확정

PRD 본문에서 근거를 못 대는 감정은 넣지 않았다.

| # | key | 한국어 라벨 | PRD 근거 (원문) | 장면 지시 |
| --- | --- | --- | --- | --- |
| 1 | `anxiety` | 불안 | §15 "😰 불안", §2 "미래가 불안함 / 돈 걱정" | 눈을 감고 가부좌한 부처. 발 아래 잔잔한 물결. 새벽빛이 옆에서 낮게 든다. 의미: 흔들리는 환경 속 평정 |
| 2 | `anger` | 분노 | §15 "😡 분노", §2 "회사 사람 때문에 화남" | 표정은 평온, 손은 무릎 위. 붉은 낙엽이 공중에 몇 장, 바람이 잦아드는 순간. 의미: 억누르지 않고 지나가게 둠 |
| 3 | `loss` | 이별·상실 | §15 "💔 이별·상실" | 석양. 연꽃잎 서너 장이 천천히 떨어진다. 화면 오른쪽 절반이 비어 있다. 의미: 무상과 놓아줌 |
| 4 | `comparison` | 비교·열등감 | §15 "🥲 비교·자존감", §7 "#비교" | 크기가 다른 산 셋. 각 산 위로 **같은 밝기**의 햇빛. 부처는 가장 낮은 산 위에 앉아 있다. 의미: 다른 길, 같은 가치 |
| 5 | `choice` | 고민·선택 | §15 "😵‍💫 고민·선택", §2 "선택을 못 하겠음" | 갈림길과 여러 갈래 돌길. **부처는 길을 가리키지 않고 조용히 앉아 있다.** 손은 선정인 | 
| 6 | `sleepless` | 잠 못 드는 걱정 | §15 "🌙 잠·걱정" | 달빛. 작은 연꽃 모양 등 하나. 지반은 남색이 아니라 **따뜻한 밤색** |
| 7 | `attachment` | 집착·미련 | §7 태그 "#집착", §9 "**갈애** — 원하는 것을 강하게 붙잡거나…" | 손바닥을 위로 편 부처. 손 위 물이 손가락 사이로 흘러 나간다. 물은 쥐려 할수록 빠져나간다 |
| 8 | `emptiness` | 무기력·공허 | §2 "아무것도 하기 싫음" | 잎이 다 진 마른 가지 아래. 가지 끝에 **아주 작은 새싹 하나**. 부처는 그 아래 앉아 있다 |
| 9 | `relationship` | 관계 피로 | §2 "연애로 마음이 복잡함", "회사 사람" | 긴 회랑. 여러 사람의 흐릿한 그림자가 지나간다. 부처는 기둥 옆에 앉아 그 흐름을 보고 있다 |
| 10 | `approval` | 인정받고 싶은 마음 | §7 태그 "#인정욕구" | 큰 등불 여럿 사이에 놓인 **작은 등 하나가 스스로 타고 있다**. 부처는 그 작은 등 옆에 앉아 있다 |

**fallback 은 `choice`.** 근거: PRD §15 원문이 그 장면을 "부처는 길을 가리키지 않고 조용히 앉아 있다"로
정의했다. 어떤 고민에도 어긋나지 않는 유일한 장면이다. 감정을 못 고른 답변에 `anxiety` 를 깔면
「당신은 불안하군요」로 오독된다.

**후보로 남긴 11번째:** `regret` 자책·후회. PRD 본문에 직접 근거가 없어 v1 에서 뺐다 → 11절 열린 질문 4.

```
no hard shadows, gentle rim light, subtle paper grain, flat horizon,
generous negative space, calm and contemporary, NOT photorealistic, NOT ornate temple mural
```

### 5.4 어떻게 만들 것인가

| 안 | 장단 | 판정 |
| --- | --- | --- |
| **AI 생성 + 스타일 앵커 1장** | 20장 화풍 통일을 참조 이미지로 강제. 장면이 바뀌어도 재생성 비용이 거의 0. MVP 에서 장면 정의가 흔들려도 손해가 없다 | ✅ **채택** |
| 외주 일러스트 | 품질과 저작권이 가장 깨끗하다. 하지만 20장 리드타임과 비용이 크고, **MVP 에서 장면이 바뀌면 재작업이 전부 유료** | 보조로만. 화풍이 안 잡히면 마스터 1장만 외주 |
| 스톡 이미지 | 싸고 빠르다. 그러나 **20장 화풍 통일이 불가능**하고, 실존 불상 사진은 문화재·소장기관 이미지권 문제가 붙는다 | ❌ 기각 |

**AI 생성 절차 (일관성을 잡는 법)**

1. **마스터 1장을 먼저 확정한다.** `buddha_choice_day` 를 후보 8~12장 뽑아 하나로 고른다. 이 한 장이 화풍의 정본이다.
2. 마스터를 **스타일 참조 이미지**로 넣고 나머지 19장을 생성한다. 프롬프트의 고정 블록 세 개는 절대 수정하지 않는다.
3. **시드를 고정**하고 장면 변수만 바꾼다. 시드와 프롬프트 전문을 파일별로 `docs/assets/buddha-prompts.md` 에 남긴다. 나중에 한 장만 다시 뽑을 때 다른 19장과 안 갈린다.
4. day/night 은 **같은 시드 + 광원 변수만** 바꿔 뽑는다. 자세가 달라지면 테마 전환이 점프로 보인다.

**도구 요구 조건 세 가지** (이 셋을 다 주는 도구를 고른다)
- (a) 이미지 스타일 참조 입력 (b) 시드 고정 (c) 같은 인물·구도 유지

**미확인:** 2026-09 시점 구체 모델명·버전·단가는 확인하지 않았다. 후보로 알려진 계열은 Midjourney 의 스타일·캐릭터 참조,
Google Gemini 계열 이미지 편집, OpenAI 이미지 모델이다. 셋 다 세부 기능과 라이선스 조항을 **착수일에 직접 확인**하고 고른다(11절 미확인 5).

**인수 검사 체크리스트 (10초 가계부에서 세 번 데인 자리)**

| 검사 | 왜 | 근거 |
| --- | --- | --- |
| 20장 **파일 크기가 0 이 아닌지** | "아이콘2 SVG 113개가 전부 빈 파일이었다" | 함정과 교훈 |
| 장마다 **그림의 경계 상자를 실측**해 여백이 같은지 | "아이콘 세트를 이어 붙이면 크기가 갈린다. 그 바람에 앞선 보정이 틀어졌다" | 함정과 교훈 |
| 20장을 **한 판에 나란히 띄워** 화풍이 갈리는 장을 고른다 | 한 장씩 보면 못 찾는다 | "한 장씩 렌더되는 카드는 넘기며 세야 한다" |
| **투명 배경이 아닌지** | 장면 일러스트는 불투명이어야 한다. 투명이면 다크에서 뚫린다 | 콘솔 규격 사건과 같은 부류 |
| 시트로 받았다면 **자를 때 흩어진 점**이 붙지 않았는지 | "그림 사이사이에 흰 점들이 흩어져 있었다. 그냥 자르면 아이콘마다 먼지가 붙는다" | 함정과 교훈 |

### 5.6 포맷 · 해상도 · 용량

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 포맷 | **WebP** (품질 78, 불투명) | 웹뷰 호환 폭이 가장 넓다. AVIF 는 폴백이 더 필요하다 (실기기 확인 필요 → 11절 미확인 3) |
| 원본 보관 | 1440×1440 PNG, 저장소 밖 `docs/assets/original/` | 다시 뽑을 때 필요 |

| 장당 용량 | 목표 ≤ 70KB, **상한 100KB** | 넘으면 다시 압축한다 |
| 20장 합계 | 목표 ≤ 1.4MB | 한꺼번에 받지 않으므로 번들 크기가 아니라 저장소 크기다 |
| 두는 자리 | 우리 오리진(`public/illust/`). **CDN 을 렌더 경로에 두지 않는다** | 10초 가계부: "외부 CDN 을 렌더 경로에 두지 않는다. 간헐 실패가 나면 우리 코드부터 보지 말고 「이 화면이 남의 서버를 기다리고 있나」를 먼저 본다" |
| 파일 확장자와 gitignore | **`.gitignore` 에 `*.png`·`*.webp` 가 있는지 먼저 본다** | "`.gitignore` 의 `*.png` 가 스토어 이미지를 조용히 뺀다. 이미지를 넣을 때는 `git add -f` 하고 `git show --stat` 로 장 수를 센다" |

**언제 받는가 (첫 화면을 안 늦추는 순서)**

| 화면 | 이미지 | 왜 |
| --- | --- | --- |
| 홈(고민 입력) | **없다** | PRD §3 이 홈을 입력창 중심으로 정의했다. 첫 화면 바이트가 0 이다 (원칙 P4) |
| 생성 대기 | **인라인 SVG 연꽃**. 네트워크를 안 탄다 | PRD §13 은 "부처 이미지 또는 연꽃 애니메이션"이라 했다. 이미지를 쓰면 LLM 을 기다리는 그 순간에 요청이 하나 더 붙는다 → 연꽃 SVG 로 확정 |
| 답변 | `visualTheme` 을 받은 뒤 그 한 장만 받는다 | 20장 중 1장이다 |
| 이미지가 오는 동안 | 그 감정의 `--ph-*` 단색 면 + radius 20 | 레이아웃이 튀지 않게 자리를 먼저 잡는다 (`aspect-ratio: 1`) |
| 프리페치 | 대기 화면에 들어간 순간 **fallback 2장(`choice_day`·`choice_night`)만** | 어차피 2~10초 기다린다. 나머지를 미리 받으면 20장을 다 받게 된다 |

### 5.7 감정 태그 → 이미지 파일 매핑

⚠ **이미지는 `emotionTags` 로 고르지 않는다. `visualTheme` 으로 고른다.**

PRD §16 은 "LLM이 태그를 반환하면 해당 이미지 선택"이라 했고 §28 JSON 에는 `emotionTags`(한국어 자유 문자열 배열)와
`visualTheme`(영문 단일 값)이 **둘 다** 있다. 태그로 고르면 LLM 이 `#번아웃` 같은 새 태그를 만드는 순간

## 6. 모션

원칙: **모션은 기다림을 설명하고 읽는 순서를 알려 준다. 장식하지 않는다.**

### 6.1 생성 대기 화면 (PRD §13)

PRD 원문: "화면 중앙에 차분한 부처 이미지 또는 연꽃 애니메이션. 순차 텍스트: 당신의 이야기를 살펴보고 있어요 →
닿아 있는 가르침을 찾고 있어요 → 지금 상황에 맞게 풀어보고 있어요 → 오늘 해볼 일을 정리하고 있어요.
**1~2초마다** 자연스럽게 변화."

| 요소 | 규격 |
| --- | --- |
| 연꽃 | **인라인 SVG**, 8잎, 120×120. 색 `--accent-soft` 바탕 + `--accent` 선 |
| 호흡 | `scale(1) → scale(1.04) → scale(1)`, 주기 **3.2초**, `ease-in-out`, 무한. 사람 호흡 리듬에 맞춘다 |
| 잎 순차 | 잎 8장이 `opacity .35 → 1` 을 400ms 간격으로 돌아가며 한 바퀴. 주기 3.2초와 맞물린다 |
| 문구 교체 | **1.8초마다**(PRD "1~2초" 안). 나가는 문구 `opacity 1→0` + `translateY(0→-6px)` 200ms, 들어오는 문구 `opacity 0→1` + `translateY(6px→0)` 220ms, 80ms 겹침 |
| 문구 4개를 다 돌았는데 아직 응답이 없으면 | 마지막 문구에서 멈추고 연꽃 호흡만 계속한다. **진행 막대를 그리지 않는다.** 남은 시간을 모르면서 막대를 그리면 거짓말이 된다 |
| 광고 | **없다** (4.7절) |

### 6.2 답변 등장 (PRD §26 의 ①~⑦)

| 요소 | 규격 |
| --- | --- |
| 섹션 순차 등장 | 각 섹션 `opacity 0→1` + `translateY(12px→0)`, 320ms `cubic-bezier(.22,.61,.36,1)`, **stagger 60ms** |
| 총 길이 | 7섹션 × 60ms + 320ms = **약 740ms**. 이 이상 끌면 「읽고 싶은데 못 읽게 막는 연출」이 된다 |
| 몇 번 도는가 | **한 번만.** 스크롤로 되돌아와도 다시 재생하지 않는다 |
| 마음 태그 칩 | `scale(.92→1)` + `opacity`, 220ms, stagger 40ms. 섹션 ① 등장 뒤에 이어서 |
| 「오늘의 한마디」 짙은 면 | 다른 섹션보다 **80ms 늦게** 들어온다. 여기가 시선이 멈춰야 하는 자리다 |
| 경전 `원문 보기` 펼침 | height auto 애니메이션을 쓰지 않는다. `grid-template-rows: 0fr → 1fr` 260ms |
| 일러스트 | 이미지가 도착하면 플레이스홀더 위에서 `opacity 0→1` 400ms. **크기·위치는 절대 안 움직인다**(자리를 먼저 잡아 뒀다) |

### 6.3 그 밖

| 요소 | 규격 |
| --- | --- |
| 바텀시트 | `translateY(48px→0)` + `opacity`, **220ms** `cubic-bezier(.32,.72,0,1)` · 딤 180ms `ease-out` (10초 가계부에서 이미 쓰던 검증된 값) |
| 버튼 누름 | `scale(.97)` 90ms. 색 변화는 `--accent-pressed` |
| 공유 카드 생성 | 카드 미리보기가 `scale(.96→1)` + `opacity` 280ms 로 나타난다. 카드를 만드는 동안은 같은 자리에 스켈레톤 |
| ⭐ 간직하기 | 누르면 별이 `scale(1→1.3→1)` 320ms `cubic-bezier(.34,1.56,.64,1)` 한 번. 색 `--scripture-text` |
| 탭 전환 | **애니메이션 없음.** 즉시 바꾼다. 탭은 자주 눌린다 |

### 6.4 `prefers-reduced-motion`

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .01ms !important;
    scroll-behavior: auto !important;
  }
  /* 대기 화면은 「멈춘 것」과 「고장난 것」이 구분돼야 한다.
     연꽃 호흡은 끄되, 문구는 계속 교체한다(교체 자체가 살아 있다는 신호다). */
  .waiting__lotus { animation: none; }
  .waiting__line  { transition: none; }   /* 페이드 없이 즉시 교체 */
}
```

- transform 은 전부 없애고 **opacity 만 남긴다**(120ms).
- 별 튀는 애니메이션·칩 stagger 는 완전히 끈다.
- ⚠ 대기 화면에서 모션을 전부 끄면 **멈춘 화면**이 된다. 문구 교체만은 살린다. 이게 "아직 생각 중"이라는 유일한 신호다.

## 7. 공유 카드 규격

⚠ **SDK 를 실제로 읽어 보니 공유가 둘로 갈린다.** 카드 한 벌로는 안 된다.

| SDK | 시그니처 (문서 원문) | 최소 토스 앱 버전 | 무엇을 낼 수 있나 |
| --- | --- | --- | --- |
| `Share.sendMessage` | `Share.sendMessage(message: { message: string }): Promise<void>` | 문서에 없음 | **텍스트만.** 이미지 파라미터가 없다 |
| `Share.createLink` | `Share.createLink(params: { path: string; ogImageUrl?: string }): Promise<string>` | `ogImageUrl` 은 Android **5.240.0** / iOS **5.239.0** 이상 | 딥링크 + **OG 이미지 URL**. `path` 는 `intoss://` 로 시작 |
| `File.saveBase64` | `File.saveBase64(params: { data: string; fileName: string; mimeType: string }): Promise<void>` | Android **5.218.0** / iOS **5.216.0** 이상 | 기기에 파일 저장. 카드 PNG 를 여기로 내보낸다 |

→ **산출물이 두 개다.**

### 7.1 저장·업로드용 카드 (1080×1350, 4:5)

사용자가 인스타·카톡에 직접 올리는 이미지. `canvas` 로 그려 `File.saveBase64` 로 저장한다.

```
┌─────────────────────────────────┐ 1080 × 1350
│ ↕ 96                            │
│ ├88┤  #불안  #비교  #인정욕구      │  칩 3개까지, 높이 56, 글자 30/600
│ ↕ 56                            │
│       오늘의 한마디 본문           │  68px / 1.45 / -0.02em / 700
│       (최대 4줄, 40자 상한)        │  본문 폭 904
│ ↕ 64                            │
│ ┌───────────────────────────┐   │  인용면: 배경 gold-50, radius 32,
│ │ 🌱 오늘 해볼 일 한 줄         │   │  왼쪽 세로선 8px gold-300
│ └───────────────────────────┘   │  30px / 1.6 / 최대 2줄 60자
│ ↕ 자동 (남는 높이)                │
│       [연꽃 마크]  부처의 말        │  하단 브랜딩 영역 168
│       내 고민에 맞는 가르침 받기     │  32px / 24px
│ ↕ 72                            │
└─────────────────────────────────┘
```

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 크기 | **1080×1350 (4:5)** | 인스타 피드·스토리·카톡 미리보기에서 가장 덜 잘린다 (추정) |
| 안전 영역 | 좌우 88 · 상단 96 · 하단 **168**(브랜딩 자리) | 본문 폭 904px 확보 |
| 배경 | `--bg` 또는 그 답변의 감정 톤 면. **일러스트를 배경으로 깔지 않는다** | 글자가 그림 위에 놓이면 읽기가 나빠지고, 부처 위에 글자를 얹는 것이 5.5절 금지 |
| 일러스트 | 쓰려면 하단 브랜딩 영역 오른쪽에 **120×120 작게**. 배경으로 깔지 않는다 | 같음 |
| 오늘의 한마디 | 68px, 최대 4줄, **한글 40자 상한** | 904 ÷ 68 ≈ 13.3자/줄 × 3줄 = 39.9자. 40자를 넘기면 56px 로 낮추고 4줄까지 허용 |
| 넘칠 때 | 말줄임하지 않는다. **글자 크기를 68 → 60 → 56 세 단계로 낮춘다.** 56 에서도 넘치면 그 답변은 카드를 안 만들고 텍스트 공유만 준다 | 문장을 자르면 뜻이 바뀐다 |
| 오늘 해볼 일 | 30px, 최대 2줄 60자, Action 1개만 | PRD §22 "작은 글씨로 오늘의 수행" |
| 마음 태그 | 최대 **3개**. Deep 이 4개를 줘도 3개만 | 4개면 한 줄을 넘는다 |
| 경전 | 「경전과 함께」 옵션을 고른 경우에만. 인용면 안에 번역문 2줄 + 출처 1줄 | PRD §23 |
| **고민 원문** | **절대 넣지 않는다** | PRD §23 원문: "사용자의 실제 고민 내용은 **명시적으로 선택하지 않는 이상 절대 포함하지 않는다.**" |
| 포맷 | PNG. `File.saveBase64` 의 `mimeType: 'image/png'` | |

### 7.2 링크 미리보기용 OG 이미지 (1200×600, 2:1)

`Share.createLink` 의 `ogImageUrl` 은 **URL 을 받는다.** 클라이언트 canvas 로는 못 준다.
→ **서버가 렌더해 공개 URL 로 내야 한다.** 백엔드 축 의존이다(10절 PRD 충돌 E).

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 크기 | **1200×600** | open-graph.md 원문: "이미지 사이즈는 1200 × 600으로 만들어 주세요" |
| 글자 | **최소로.** 한마디 전문을 넣지 않는다. 20자 이내 짧은 구절 또는 구절 없이 워드마크만 | open-graph.md 원문: "썸네일에 텍스트를 과도하게 넣지 마세요. (로고와 함께하는 슬로건이나 보조 텍스트는 적절한 크기와 위치에서는 허용)" |
| 금지 | 비속어·은어·정치적 표현 | open-graph.md 원문: "민감하거나 부적절한 용어를 포함하지 마세요" |
| 구성 | 왼쪽 60%: 연꽃 마크 + 「부처의 말」 워드마크 + 한 줄 보조 문구. 오른쪽 40%: 그 답변의 감정 일러스트 낮 버전 | |
| 안전 영역 | 좌우 96 · 상하 72 | **문서에 수치가 없다. 우리가 정한 값이다**(11절 미확인 4) |
| 품질 | "고화질 이미지를 사용해 주세요" | 원문 |

### 7.3 텍스트 공유 (항상 되는 길)

`Share.sendMessage({ message })` 는 문자열만 받는다. OG 이미지와 파일 저장이 둘 다 안 되는 구버전에서도
이 길은 남는다. 클립보드 권한(`{name:'clipboard', access:'write'}`)도 config 에 있다.

```
🪷 부처의 말

다른 사람의 속도가 당신의 방향을 결정하지는 않습니다.

법구경 ○○장 ○○절
내 고민에 맞는 가르침 받아보기 <링크>
```

한 문장 + 출처 + 링크. **고민 원문은 넣지 않는다.**

### 7.4 공유 경로별 폴백 순서

| 순서 | 조건 | 무엇을 준다 |
| --- | --- | --- |
| 1 | `File.saveBase64` 지원 | 카드 이미지 저장 → 「사진에 저장했어요」 안내 |
| 2 | `Share.createLink` + `ogImageUrl` 지원 | 딥링크 공유. 미리보기에 OG 이미지 |
| 3 | `Share.sendMessage` 만 | 텍스트 공유 |
| 4 | 전부 미지원 | 클립보드 복사 → 「복사했어요」 |

⚠ **버전 게이트는 반드시 `try/catch` 로 잡는다.** 10초 가계부 원문: "도메인 멤버는 미지원 버전에서
`UNSUPPORTED_APP_VERSION` 에러를 **던지고**, deprecated 된 옛 함수는 `undefined` 나 `'ERROR'` 를 **반환**한다.
2.x 습관대로 반환값만 확인하면 앱이 통째로 죽는다." 그리고 에러를 **메시지 문자열로 판정하지 않는다**
(`error.name === 'UNSUPPORTED_APP_VERSION'` 로 본다).

⚠ **`File.saveBase64` 의 `data` 가 base64 알맹이인지 data URL 인지 문서에 안 적혀 있다.**
10초 가계부에서 정확히 같은 함정을 밟았다: "`Device.getPhotos`·`Device.openCamera` 가 돌려주는 `ImageResponse` 의
필드 이름은 `dataUri` 인데 **`data:image/jpeg;base64,` 접두사가 붙어 오지 않는다.** (...) 이걸 모르고
서버에서 `value.startswith("data:")` 로 막았더니 실기기 사진 등록이 처음부터 끝까지 전부 422 였다.
이틀 동안 한 장도 통과하지 못했다." → **첫날 실기기에서 두 형식을 다 넣어 본다.**

## 8. 앱 아이콘 · 브랜딩

규격(콘솔 화면 실측): **정사각형 600×600 · PNG · 배경 필수(투명 불가) · 라운드 모서리 사용 불가.**

> 10초 가계부 원문: "「라운드 모서리 금지」가 핵심이다. 플랫폼이 알아서 마스킹하므로, 우리가 둥글게 만들어 두면
> 두 번 깎여 아이콘이 작아 보이거나 이중 윤곽이 생긴다. **꽉 찬 정사각형**을 올려야 한다."
> 그리고 "콘솔 규격을 안 읽고 파일부터 올리려 했다. (...) 그대로 올렸으면 아이콘이 두 번 깎여 작아 보이거나 반려됐을 것이다."

### 8.1 세 안

| 그림 | lotus-300 → lotus-500 연꽃 5잎, 중앙 gold-300 술 | 아이보리 말풍선, 그 안에 gold-300 연꽃 한 송이 | 아이보리 선 두 줄로 반쯤 감은 눈매, 이마에 작은 연꽃점 |

**추천 B안.** 근거: 앱 목록에서 우리 제품을 「부처 명언 앱」과 갈라 주는 유일한 요소가 「고민을 말한다」는 점이다(PRD §1).
아이콘이 그것을 말해야 한다. 그리고 바탕이 브랜드 컬러 `#B34557` 이라 콘솔 `brand.primaryColor` 와 한 몸으로 읽힌다.

**C안은 마지막에 고른다.** 위험 ②가 문화적 판단이라 우리가 혼자 결정할 문제가 아니다.

### 8.2 제출 전 검사 (10초 가계부에서 반려를 막은 검사)

1. **24px·48px 축소 미리보기**를 만들어 형태가 남는지 본다. 토스 홈 미리보기가 그 크기다.
2. **라운딩 마스크를 씌운 미리보기**를 만들어 이중 윤곽이 없는지 본다.
3. 모서리까지 색이 차 있는지 본다. 단색으로 덮지 말고 **각 행에서 색이 있는 구간을 양옆으로 늘려** 채운다(그라데이션이 끊기지 않게).
4. 투명 픽셀이 0인지 확인한다(`RGB` 로 저장).
5. **다크 로고를 비워 두지 않는다.** 10초 가계부는 "다크모드 로고는 비워 뒀다(파일이 없다)". 이번엔 같이 만든다.

### 8.3 워드마크

- 한글 「부처의 말」. 브랜드 이름은 한글 권장(플랫폼 규칙).
- 굵기 700, 자간 -0.02em. 「부처의」와 「말」 사이는 보통 띄어쓰기 하나.
- 워드마크 옆 연꽃 마크는 워드마크 **높이의 1.2배**. 그보다 크면 마크가 이름을 잡아먹는다.
- 워드마크에 부처 그림을 붙이지 않는다. 5.5절 「부처 옆 광고 금지」와 같은 이유로, 워드마크는 어디든(광고 근처 포함) 갈 수 있어야 한다.

## 12. 대비비 계산 스크립트 (시안 QA 에 그대로 쓴다)

2.5~2.7절 숫자는 전부 이 코드로 계산했다. 시안 HTML 을 만든 뒤 **같은 스크립트를 한 번 더 돌린다.**

```python
def srgb(c):
    c = c / 255
    return c / 12.92 if c <= 0.04045 else ((c + 0.055) / 1.055) ** 2.4

def lum(h):
    h = h.lstrip('#')
    return (0.2126 * srgb(int(h[0:2], 16))
          + 0.7152 * srgb(int(h[2:4], 16))
          + 0.0722 * srgb(int(h[4:6], 16)))

def cr(fg, bg):
    a, b = lum(fg), lum(bg)
    hi, lo = max(a, b), min(a, b)
    return round((hi + 0.05) / (lo + 0.05), 2)
```

기준: 본문 **4.5** · 18.66px 이상 굵은 글자 **3.0** · UI 경계와 포커스 **3.0**.

> 10초 가계부 원문: "「뭔가 답답한데」로 끝나던 것을 숫자로 바꾸는 방법이다. (...) 이번에 이 방법으로
> 화면 14갈래에서 차이 150건을 뽑았고 적대 검증을 지나 78건이 확정됐다. 스크린샷만 보면 절반도 못 찾는다.
> **사람 눈은 2px 을 못 본다.**"
