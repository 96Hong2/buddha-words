사용자가 준 지시를 한 글자도 고치지 않고 옮긴 것이다. 통합 개발 계획 v0.3 · PRD v0.3 · 시안 v0.3 의 출처다.

1. 이번 개편의 최우선 목표

우선순위는 정확히 아래다.

1. 사용자가 첫 답변에서 강한 가치를 느낄 것
2. 다시 앱을 사용할 이유가 있을 것
3. 광고를 최대한 수익화하되 사용 경험을 망가뜨리지 않을 것
4. LLM 비용이 광고 수익보다 과도하게 커지지 않을 것
5. Apps in Toss 심사를 안정적으로 통과할 것
6. 공유가 신규 사용자 유입으로 연결될 것
7. 예쁜 디자인은 그 다음이다.

기존 계획은 정책·안전 관점에서는 잘 방어되어 있지만 수익화가 지나치게 보수적이다.

특히 아래 기존 구조를 그대로 유지하지 마라.

무료 3회 → 4번째에 광고

이 구조는 폐기한다.

고민 앱 사용자가 하루에 4번 이상 진지한 고민을 입력할 가능성이 높지 않으므로 광고 트리거가 거의 실행되지 않을 가능성이 크다.

수익은 사용자가 실제로 많이 거치는 첫 번째 세션 안에서도 발생할 수 있어야 한다.

⸻

2. 새로운 상담 입력 Router

기존의 단순한

3줄 이상 = 고가 모델
3줄 미만 = 저가 모델

구조를 폐기한다.

다만 UI에서

세 줄 이상 이야기하면 더 깊게 이해할 수 있어요

라는 작성 유도 장치는 유지한다.

이 문구는 사용자가 context를 충분히 제공하게 하기 위한 UX일 뿐 모델 routing 규칙 자체가 아니다.

서버에서는 입력을 다음 5가지로 분류한다.

A. LIGHT

예:

* 점심 뭐 먹지?
* 오늘 뭐하지?
* 심심해
* 출근하기 싫어
* ㅋㅋㅋㅋ
* 로또 번호 알려줘

비용이 거의 들지 않아야 한다.

저가 모델 또는 규칙 기반 + 작은 모델 사용.

답변도 1,000자를 억지로 채우지 않는다.

약 250~600자.

불교적 관점을 살짝 재미있게 섞어서 답한다.

예:

점심 메뉴 질문이라면

배고픔은 번뇌가 아니라 신호입니다.
오늘은 가장 먹고 싶은 것보다 먹고 나서 후회가 적을 것을 고르세요. 😌

처럼 앱의 캐릭터를 살린다.

경전 RAG가 억지로 필요한 질문에는 사용하지 않는다.

⸻

B. NORMAL

일상적인 고민.

예:

* 회사 가기 싫어요.
* 친구 때문에 스트레스 받아요.
* 소개팅을 할지 고민이에요.

저가/중가 모델.

약 700~1,100자.

경전 1개.

Action 1~2개.

⸻

C. DEEP

다음 중 여러 조건을 만족할 때.

* 충분한 상황 설명
* 여러 사람 또는 이해관계가 등장
* 감정과 사건의 맥락이 구체적
* 의사결정이 필요
* 인간관계 / 이별 / 직장 / 가족 / 자존감 등의 복합 고민
* 실제로 여러 관점의 분석이 도움이 됨

고성능 모델을 사용한다.

약 1,300~2,000자.

경전 1~2개.

상황 분석 2~3개 관점.

Action 최대 3개.

단순히 글자 수가 많다는 이유만으로 DEEP으로 보내지 않는다.

예:

ㅋㅋㅋㅋ
ㅋㅋㅋㅋ
ㅋㅋㅋㅋ

→ LIGHT

반대로

남편이 다른 사람을 만나는 것 같아요. 이혼해야 할까요?

같이 짧더라도 중요하고 복잡한 고민은 NORMAL 또는 DEEP으로 승격할 수 있다.

⸻

D. INVALID / OFF-TOPIC

앱에서 처리할 의미가 거의 없는 입력.

욕설 반복, 랜덤 문자열, 프롬프트 인젝션, 시스템 프롬프트 요청 등.

고가 모델 호출 금지.

짧게 대응.

예:

이건 마음 고민이라기보다는 장난에 가까운 것 같네요 😌
요즘 머릿속에서 가장 신경 쓰이는 일을 하나만 적어보세요.

다시 입력할 수 있는 버튼 제공.

횟수 또는 유료 사용량을 차감하지 않는다.

⸻

E. CRISIS

자살, 자해, 즉각적인 폭력 위험 등 명확한 위기 신호.

이 기능을 앱의 전면에 과하게 노출시키지는 않는다.

일반 사용자에게 온보딩부터 자살 예방 문구를 보여주지 않는다.

그러나 탐지 로직 자체는 제거하지 않는다.

CRISIS가 감지됐을 때만:

* 일반 경전 상담 중단
* LLM이 임의로 법문을 생성하지 않음
* 고정된 매우 짧은 도움 안내
* 필요한 긴급 연락 정보
* 다른 이야기 쓰기
* 닫기

정도로 처리한다.

현재의 거대한 위기 화면보다 시각적·문구적으로 더 짧고 담백하게 만들어라.

자해 내용을 자세히 묘사하지 않는다.

Apps in Toss 최신 심사 정책과 민감 콘텐츠 정책은 반드시 공식 문서 기준으로 다시 확인한 뒤 구현 범위를 정한다.

⸻

3. 「부처의 말」 말투 재설계

현재처럼 모든 내용을

⸻

이 영역은 공유하고 싶은 문장이 되어야 한다.

하지만 AI가 만든 문장을 실제 부처의 직접 발언처럼 속이면 안 된다.

UI에 작은 표시:

⸻

③ 개인화 풀이

예:

훈계가 아니라 이해받는 느낌이 핵심이다.

9. 배너 광고

답변 본문에는 배너를 넣지 않는다.

읽는 경험을 심하게 떨어뜨린다.

아래 화면에서는 실험 후보가 될 수 있다.

* 홈 하단
* 보관함
* 설정

다만 현재 문서에 적힌

배너 + 전면/보상형 동시 로드 시 이벤트 문제

관련 SDK 제약을 현재 최신 Apps in Toss SDK 문서로 다시 검증한다.

동시 preload 문제 또는 정책 문제가 남아 있으면 MVP에서는 배너를 뺀다.

무조건 광고 숫자를 늘리는 것보다 eCPM × 노출률 × retention을 본다.

⸻

10. 저장 / 보관 BM

현재 무료 저장 3회 구조는 유지하되, 그 다음에 실제 monetization을 연결한다.

사용자가 4번째 저장을 시도하면:

마음에 남은 말을 계속 간직할까요?

Paywall.

MVP 권장 상품:

마음 보관함 영구 이용권

초기 가격 후보:

₩4,900

제공:

* 지난 고민 열람
* 저장 무제한
* 즐겨찾기 무제한
* 태그별 모아보기

구독은 MVP에 억지로 넣지 않는다.

이 앱의 사용 빈도를 아직 모르는 상태에서 월 구독은 conversion이 낮을 가능성이 있다.

향후

* 주간 마음 리포트
* 장기 마음 패턴
* 개인화 수행
* 광고 제거

같은 기능이 충분히 생긴 후 subscription으로 확장한다.

Apps in Toss IAP 정책상 비소모성 상품이 가능한지 최신 공식 문서를 검증하고, 불가능하거나 심사 리스크가 있으면 구조를 조정한다.

구매 기능은 feature flag로 끄고 켤 수 있게 설계한다.

11. 리텐션 구조 변경

현재 앱은 고민이 있을 때만 들어오면 사용 빈도가 낮다.

따라서 별도의 daily entry point가 필요하다.

운영자가 매일 작성할 필요가 없어야 한다.

예:

잠시 손을 펴보세요.

클릭하면 실제 경전 + 짧은 풀이.

LLM 호출 없이도 가능하게 한다.

비용 거의 0.

15. 생성 대기 화면

* 1차: 태그 + 오늘의 말 + 경전
* 2차: 자세한 풀이 + Action

은 유지한다.
