# 광고와 사용량

- 광고 자리는 `AdPlacement = 'extension' | 'continue' | 'save'` 셋뿐이고 **셋 다 사람이 버튼을 눌러야 뜬다.** 새 자리를 만들려면 `docs/plan/00-통합-개발-계획.md` 1.6절을 먼저 고친다.
- **종류는 광고 그룹 id 가 정한다**(전면형·보상형이 같은 API). 자리별 종류는 `AD_KIND` 에 있고, 이어가기만 `VITE_AD_CONTINUE_KIND` 로 갈린다. 기본은 보상형이다.
- 금지 자리: 고민 작성 중 · 첫 제출 직후 · 답변 블록 사이 · 경전과 분석 사이 · 대기 화면 · 위기 화면 · **위로 답변 화면** · **진입 카드** · INVALID 화면.
- `loadFullScreenAd` → `loaded` → `showFullScreenAd`. 사전 로드. 한 화면에서 광고 그룹 하나만, 순차 로드.
- 보상은 `userEarnedReward` 에서만 지급한다. `dismissed` 는 취소다. **닫은 사람에게 주면 SDK 가이드 위반이다.** 5초만 보면 답을 주던 판이 그래서 뒤집혔다(2026-09-20).
- ⚠ **보상 토큰 서버 검증은 아직 없다.** 서버는 화면이 보낸 `adWatched` 를 그대로 믿는다. 그 틈은 코드로 못 막으니 화면 쪽 판정을 느슨하게 하지 않는다.
- 광고 버튼 안에는 **「광고」 배지**가 붙는다(토스 SSP 「Ad 표기 유지」). 배지를 지우거나 숨기지 않는다.
- **버튼 라벨에 「광고」와 몇 초짜리인지를 함께 적는다** (「30초 광고 보고 간직하기」 · 「30초 광고 보고 답변 받기」). 2026-09-19 에 바뀐 규칙이다: 초를 안 적으면 얼마나 참아야 하는지 모른 채 전면 광고를 만나고, 그러면 중간에 닫는다. 배지는 그대로 둔다.
  - **전면형으로 돌리는 판에서는 「광고 보고 ~받기」를 쓰지 않는다.** 그 판은 닫아도 답이 나오므로 거짓말이 되고, 초도 문서에 없어 적지 않는다.
- 시트 제목·부제에서는 광고를 말하지 않고 사용자가 얻는 것을 앞에 둔다(「이야기를 이어가 볼까요?」). 「광고 클릭하면」 류 문구 금지. 광고 컨테이너 안에 우리 글자 없음.
- **베푼 것을 세는 문장을 쓰지 않는다.** 「첫 이야기는 광고 없이 드렸어요」처럼 앞서 무료로 준 것을 상기시키면 다음 요구가 청구서로 읽힌다.
- 광고를 못 띄우는 상황(`isSupported()` false · no fill · 이 기기 광고 끄기)에서는 Extension CTA 를 숨기고 이어가기는 시트 없이 허용한다. 광고 때문에 기능을 막지 않는다.
- 사용량: 하루 첫 NORMAL·DEEP 무료 → **그다음은 광고를 본 만큼 계속 이어간다. 하루 천장은 없다**(2026-09-20 폐지. 광고를 보는 사람을 막고 있었다). LIGHT 하루 10회 소프트 상한. INVALID·CRISIS·SOLACE 는 세지 않는다. 기준 시각은 사용자 시간대 자정. 성공한 생성만 센다. 확인이 아니라 예약(`pending` 행 + 멱등키).
- 막는 일은 **서버만** 한다. 화면은 문을 닫지 않는다. 문은 둘이다: 사람마다 **분당 `usage.MAX_PER_MINUTE`** 건(`too_fast`), 그리고 **전역 일일 예산**(`budget_blocked`). 둘 다 정상 사용자를 안 막는다.
- ⚠ **횟수를 세어 보여 주는 문구를 쓰지 않는다**(「오늘 N번 더」). 셀 것이 없고, 광고를 봐도 막히는 줄로 읽힌다.
- 개발·QA 광고 ID 는 `ait-ad-test-rewarded-id` · `ait-ad-test-interstitial-id`. 실광고 ID 로 테스트하지 않는다. **운영 번들에 이 문자열이 남으면 콘솔 검토가 반려한다**(1호 제품 실제 사례). `import.meta.env.DEV` 뒤에 두어 빌드에서 지워지고, `tools/check_bundle.mjs` 가 한 번 더 센다.
