# 검증

- 검증은 e2e 화면 한 겹이 기본이다. 구현 먼저, 그다음 `frontend/e2e/` 에서 실제 화면·동작을 확인한다(`npm run e2e`, frontend 에서).
- 목으로 격리한 단위 테스트를 만들지 않는다. 단위 테스트는 순수 로직(라우터 픽스처 · 스키마 검증 · 사용량 계산)에만.
- 실패해야 하는 검증은 실패한 채로 둔다. skip · 단언 약화 · 기대값 베끼기 금지.
- 일부러 깨뜨려 확인은 새 검증 장치를 만든 그 자리 한 곳만.
- e2e 는 익명키 격리 fixture 를 반드시 쓴다. 없으면 두 번째 테스트부터 전부 429 다.
- LLM 은 `stub` provider 다이얼(지연 · 실패 · 거절 · crisis · light · invalid)로 분기를 만든다. 실제 모델 호출은 실측 1시간과 실기기 QA 에서만.
- 광고·결제·익명키 실발급은 devtools mock 이 못 본다. 콘솔 QR 실기기 목록을 PR 에 적는다.
